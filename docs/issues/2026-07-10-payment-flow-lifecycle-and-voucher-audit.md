# 收付流水作废更正与凭证审计后续项

**状态**：🔄 待实施
**来源**：经营台账与收付流水主计划收口后的非阻断增强项
**范围**：仅收付流水生命周期和凭证下载审计；不改变已落地的经营台账查询、分摊、服务费和统计口径。

## 背景

当前实收/实付已只允许通过 `OperationalPaymentFlow` 与 `PaymentAllocation` 写入，旧直接改 `paid_amount` 入口已下线。主链路可用，但流水登记错误后还缺少显式作废/更正动作，可选凭证附件也缺少下载审计证据。

## 已定方案

1. 不做财务红字冲销，不引入会计凭证概念。
2. `active` 流水可作废为 `voided`；原记录不删除，其分摊立即不再参与实收/实付汇总，所有受影响台账在同一事务中重算。
3. 更正为单一事务：原流水转 `corrected`，创建一条新 `active` 流水及其分摊，新记录通过 `corrected_from_flow_id` 指向原记录。
4. 作废/更正必须记录操作人、操作时间和原因，并沿用收付流水所在项目/主体的数据范围鉴权。
5. 凭证附件继续复用现有 Attachment 存储与鉴权；下载时记录用户、流水、附件、时间和结果，不新建一套凭证表。
6. 租金台账与服务费台账继续使用分类查询载荷；当前 UI 不需要混排，不新增统一混合列表响应。

## 完成标准

- ORM / migration / schema 表达原流水关联和操作审计字段。
- Service 在一个事务内完成作废或更正、分摊失效/新建和受影响台账重算。
- API 和前端只暴露可执行的明确动作，不允许直接写 `status` 或 `paid_amount`。
- 凭证下载有可查询审计证据，未授权主体不可读取附件或审计元数据。
- 覆盖重复作废、更正作废流水、跨主体分摊、部分失败回滚和并发更正测试。
