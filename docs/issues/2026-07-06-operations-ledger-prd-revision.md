# 运营台账与经营口径 PRD 修订建议

**状态**：🔄 实施中 / 后端底座已启动
**来源**：2026-07-06 需求层面追问与澄清
**范围**：仅记录 PRD、领域模型、API 契约与追踪矩阵的修订建议；不包含代码实现。

## 背景

现行 PRD 已明确“项目”为普通用户主工作对象，并覆盖资产、合同、台账、客户、分析和权限。但进一步从运营方运营专员视角复核后，发现当前 PRD 对“项目主入口”“合同关系”“台账”“收入/收缴/成本”等概念仍有偏差：

- “项目主入口”容易被误解为取代资产、合同、客户、台账等直接入口。
- “合同关系”是内部建模术语，不应作为普通用户界面对象名。
- “财务台账”命名过重，容易把系统拉向财务总账；实际需要是运营侧经营台账。
- 代理运营下“终端租户租金收缴”和“运营方服务费收入”需要拆开。
- 承租转租下除下游租金收入外，还需要记录上游承租成本。
- 当前“只登记累计实收金额”的台账口径不足以支撑无财务系统场景下的追溯。

## 已确认的产品原则

1. **项目是默认主入口，但不是唯一入口。**
   普通运营用户大部分时间从项目进入；资产、合同、客户、经营台账、经营分析仍保留同级直接入口，用于跨项目查询、专项维护和整体视角。

2. **项目是运营管理单元，不强绑定物理地点。**
   项目可以是园区、楼宇、片区或一组由同一运营方按同一经营目标管理的资产组合。同一资产同一时点只能归属一个当前有效项目。

3. **项目可以同时承载承租转租和代理运营。**
   具体合同/协议仍按业务类型表达；统计和分析按模式拆分展示。

4. **历史经营数据不随资产调项目回写。**
   资产调整项目只影响当前和未来；历史合同、经营台账和分析口径按生成时归属固化。

5. **项目必须绑定运营管理方。**
   产权方挂资产，运营方挂项目，资产当前运营方由当前项目派生。

6. **“合同关系”不作为用户界面术语。**
   该词可保留为内部模型术语；用户侧展示为“合同与协议”“租赁与代理”“承租转租”“代理运营”等业务语言。

## 导航与页面结构建议

### 左侧导航

建议将导航调整为：

1. 工作台
2. 项目运营
3. 经营台账
4. 合同中心
5. 资产资源
6. 主体客户
7. 经营分析
8. 系统管理

关键点：

- “项目运营”是默认主入口。
- “经营台账”“合同中心”“资产资源”“主体客户”是同级直接入口，不被项目取代。
- “经营台账”替代“财务台账”命名，避免财务总账误解。

### 项目详情

项目详情应展示项目内经营全貌：

- 当前资产摘要
- 终端租户收缴摘要
- 运营方收入摘要
- 运营方成本摘要
- 经营结果摘要
- 合同与协议摘要
- 项目风险
- 项目分析

“合同与协议”摘要展示真实合同/协议行：

- 承租合同
- 转租合同
- 委托协议
- 直租合同

每行应展示合同号、合同类型、对方主体、关联资产、起止日期、状态、关键金额或服务费比例。合同号可点击跳转合同明细页；关联资产可跳转资产详情；相关台账可跳转经营台账过滤视图。

### 合同中心

合同中心面向用户展示合同/协议本身，不展示内部聚合对象。支持按项目、资产、客户、产权方、运营方、合同号、合同类型筛选：

- 承租合同
- 转租合同
- 委托协议
- 直租合同

合同明细必须保留盖章扫描件作为事实底座，每份合同/协议至少一份扫描件，支持预览、下载和维护，不允许删到 0。

## 经营台账口径

经营台账建议拆为四类业务视图。

| 视图 | 业务含义 | 包含款项 | 是否产生逾期 |
|---|---|---|---|
| 终端租户收缴 | 终端租户租金收缴完成情况 | 承租转租下游租金；代理直租租金 | 是 |
| 运营方收入 | 运营方自身经营收入 | 承租转租下游租金收入；代理服务费收入 | 否 |
| 运营方成本 | 运营方承租成本 | 承租转租上游租金成本 | 否 |
| 服务费结算 | 产权方向运营方支付代理服务费 | 代理服务费应收、实收、未收 | 否 |

### 终端租户收缴

终端租户收缴是运营专员的核心执行视图，统一包含：

- 承租转租：终端租户 → 运营方 的转租租金
- 代理运营：终端租户 → 产权方 的直租租金

代理直租租金不是运营方收入，但仍进入终端租户收缴，因为运营方需要管理和跟进租户付款。

默认列表按租户聚合，支持展开到账期明细。字段建议包括：

- 租户
- 项目
- 资产 / 铺位
- 模式：承租转租 / 代理直租
- 收款对象：运营方 / 产权方
- 账期
- 应收租金
- 实收租金
- 未收租金
- 是否逾期
- 跟进状态
- 下次跟进日期

逾期只属于终端租户租金收缴。运营方成本未付、服务费未收不产生逾期。

### 运营方收入

运营方总收入可以汇总，但必须拆项展示：

- 承租转租租金收入
- 代理服务费收入

代理直租租金不计入运营方收入，只作为代理服务费计算基数。

MVP 不引入会计收入确认口径，不做权责发生制摊销、开票、税票或财务总账。承租转租下游租金应收/实收即运营台账口径下的租金收入应收/实收。

### 运营方成本

承租转租上游租金作为运营方成本，记录：

- 应付成本
- 实付成本
- 未付成本

不做逾期口径，不产生逾期通知。

代理运营模式下，MVP 不跟踪除服务费结算外的其他运营成本，如人工、维修、招商或管理成本。

### 服务费结算

代理服务费链路拆为两段：

1. 终端租户 → 产权方：代理直租租金收缴
2. 产权方 → 运营方：代理服务费结算

服务费规则：

- 服务费应收 = 代理直租租金实收 × 委托协议服务费比例。
- 当前业务中服务费比例存在历史差异：当前合同 30%，更早合同 20%。
- 服务费比例来自直租合同明确关联的委托协议。
- 服务费按租金账期月份 / 项目 / 委托协议 / 产权方汇总生成，不逐笔生成。
- 服务费比例和服务费归属月份均按租金账期，不按实际收款月份。
- 服务费台账生成后固化比例、基数和来源账期。
- 后续租金实收更正不应静默覆盖已生成服务费应收；来源租金条目被合同更正重算跳过时，既有服务费台账不自动重算或覆盖，派生服务费来源不一致风险并交由人工处理，未生成服务费的账期按修正后实收进入后续月度生成。
- 尚未生成服务费应收的，按修正后的租金实收进入月度结算。

直租合同必须明确关联一份委托协议。系统可以按同项目、同产权方、同运营方、账期落在委托协议有效期内自动推荐，但用户必须确认。若命中多份或未命中，必须人工选择或补齐委托协议。

每条可计算服务费的租金账期必须命中单一委托协议比例。若账期跨比例区间，系统提示拆分账期，不做自动按天拆分。

## 收付流水与账期归属

当前 MVP 建议先支持轻量收付流水，而不是只修改累计实收 / 实付金额。

适用范围：

- 终端租户租金收缴流水
- 代理服务费收款流水
- 承租上游成本付款流水

流水字段建议：

- 发生日期
- 金额
- 登记人
- 备注
- 可选凭证附件

规则：

- 实收 / 实付由流水汇总派生。
- 一笔收款可人工分摊到多个账期，系统校验分摊金额合计。
- 凭证附件可选，不强制；不上传不阻断登记。
- 经营分析默认按账期归属；流水保留实际发生日期。
- 经营台账默认按账期月份筛选，同时支持收付发生日期筛选。

账期口径示例：

- 筛选 2025-12 时，分母为 2025-12 账期应收租金。
- 分子为这些 2025-12 账期截至当前已登记实收的金额，不管实际收款发生在 2025-12 还是 2026-01。
- 现金发生记录通过流水发生日期筛选和导出查看，MVP 不做独立现金流分析。

## 逾期与跟进

逾期金额和收缴率应由系统按账期和实收流水派生，不允许人工直接翻改逾期状态。

但为了适配未接财务系统的现实，MVP 应允许维护轻量运营跟进状态。跟进状态不改变逾期金额、收缴率或实收金额。

建议状态：

- 待跟进
- 已联系
- 承诺付款
- 争议中
- 线下已收待登记
- 暂缓跟进

可选字段：

- 下次跟进日期
- 跟进备注

不做催缴工单、指派、审批、催缴成功率统计。

## 项目经营结果

项目经营结果的金额默认看已登记实收 / 实付，时间归属仍按账期口径：

```text
经营净流入（已登记实收实付） = 运营方收入实收 - 运营方成本实付
```

同时提供应收应付口径切换：

```text
账面经营差额（应收应付） = 运营方收入应收 - 运营方成本应付
```

界面应避免使用“利润”作为 MVP 核心指标名，避免引入会计利润口径。

项目详情汇总指标默认按账期口径展示。若用户要看实际某月登记了哪些收付款，从项目页跳转经营台账，并按发生日期筛选。

## 经营分析重组建议

经营分析首页建议按四组指标重组：

### 终端租户收缴

- 租金应收
- 租金实收
- 租金未收
- 逾期租金
- 收缴率

### 运营方收入

- 承租转租租金收入
- 代理服务费收入
- 总收入

### 运营方成本

- 承租上游租金成本
- 已付成本
- 未付成本

### 经营结果

- 经营净流入（已登记实收实付）
- 账面经营差额（应收应付）

MVP 不做独立现金流分析；实际收付日期用于经营台账筛选、流水查询、审计和导出。

## 通知范围

MVP 通知只覆盖：

- 终端租户租金到期
- 终端租户租金逾期
- 合同 / 协议即将到期
- 合同 / 协议已到期
- 系统通知

不做：

- 运营方成本未付提醒
- 服务费未收提醒

## 建议验收场景

1. 运营专员从项目进入，查看该项目当前账期终端租户收缴、运营方收入、运营方成本和经营结果。
2. 运营专员从全局经营台账进入，跨项目筛选所有终端租户逾期租金。
3. 代理直租租户登记实收租金后，该金额进入终端租户收缴，但不进入运营方租金收入。
4. 月度服务费结算按代理直租租金实收、租金账期和委托协议历史比例生成服务费应收。
5. 租户补缴历史账期租金时，收缴率和服务费归属回补到租金账期，流水保留实际收款日期。
6. 承租转租上游租金生成运营方成本，记录应付、实付、未付，但不产生逾期提醒。
7. 一笔租户收款可分摊到多个账期，实收由流水汇总派生。
8. 终端租户未收清且账期到期后自动派生逾期；用户只能维护跟进状态，不能手工改逾期事实。
9. 项目详情合同号点击进入合同明细；合同明细可返回项目、资产和经营台账上下文。
10. 经营分析首页按终端租户收缴、运营方收入、运营方成本、经营结果四组展示。
