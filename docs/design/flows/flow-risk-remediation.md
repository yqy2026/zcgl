# Flow · 风险处置（下钻 → 改源数据 → 派生消除）

- **角色**：运营操作员 / 运营管理
- **触发**：工作台待办或项目风险摘要出现一条风险，要处置
- **价值**：风险是经营健康的实时信号；这条流决定了「风险」在产品里是**派生提示**还是**工单**——本系统选前者

## 主流程

| # | 用户动作 | 页面 | API | 校验门 / 口径 | 出错分支 |
|---|---|---|---|---|---|
| 1 | 在工作台/项目风险摘要看到风险 | Dashboard / ProjectDetail 风险区 | `GET /projects/{id}/risks` | 风险类型：人工标签、合同到期、付款逾期、空置、产权证数据质量、`ledger_stale_after_correction`——**全部由当前数据实时派生** | — |
| 2 | 点风险下钻到源对象 | 对应详情页（合同/产权证/台账/资产） | 对应详情 API | 风险**只读**、不可在风险项上操作 | — |
| 3 | 在源对象上改源数据 | 源对象编辑页 | 对应更新 API | 如：补齐证照信息、修正权利人/资产关联、对账修正台账、续约新合同 | 改动需通过该对象自身的校验门 |
| 4 | 风险**自然消除** | 风险摘要（下次渲染） | — | 风险由实时派生，源数据修正后下次计算即不再出现 | — |

## 关键 UX 约束（**整条流的核心，最容易做错**）

- **没有「标记已处理 / 关闭 / 忽略」按钮**。风险不是工单——它不可手工关闭、不单独建处置流程、不指派处理人。UI 必须引导用户**去改源头**，而不是给一个让风险消失的按钮。
  - 反例（架构禁止）：在风险项上放「处理」按钮把它标灰。这会退回 ADR-0005/0007/0008 删掉的「手工标记位」老路，制造「显示已处理但数据仍不一致」的假象。
- **产权证数据质量风险**只在资产详情产权证区、产权证详情/编辑页、项目风险摘要出现，**不进全局搜索**。
- **逾期/陈旧已收风险**：处置入口是 [实收登记](flow-ledger-settlement.md) / 合同更正对账，而非风险项本身。
- 风险**只读 + 下钻 + 改源**，是「派生优于手工标记位」原则在 UX 上的直接体现——这是本系统的脊梁，UI 不能破坏它。
