# Flow · 合同补录链路（扫描件 → 解析确认 → 台账）

- **角色**：运营操作员（运营方 × 操作）
- **触发**：收到一份盖章合同，要录入并据此生成台账
- **价值**：这是 PRD §3.2「核心经营链路真实可用」使用信号的主链路

## 前置条件

- 合同主体（出租方/承租方/权利人）已建档并**审核通过**（已审核 Party）。
- 覆盖资产已在资产主档。
- 项目已建；合同关系已建或将在步骤 1 建。

## 主流程

| # | 用户动作 | 页面 | API | 校验门 / 口径 | 出错分支 |
|---|---|---|---|---|---|
| 1 | 在项目下选定或新建合同关系 | ProjectDetail → ContractGroupForm | `POST /contract-groups` | 合同关系**锁单项目**、单条不混用经营模式（PRD §6.2） | 覆盖资产跨项目 → 拒绝 |
| 2 | 在关系内新增合同，上传盖章扫描件 | ContractInGroupForm | `PUT /contracts/{id}/attachments*` | 必留 **≥1 盖章扫描件**（事实底座，§6.5） | — |
| 3 | （可选）对扫描件发起 OCR/AI 解析 | 解析确认页 | `POST /extraction-sessions`（`target_type=contract`） | 解析仅辅助 | 解析失败/超时 → 可重试或**完全手工补录**继续 |
| 4 | 逐字段确认/修正；处理低置信；选择已审核 Party 与既有资产 | 解析确认页 | `GET /extraction-sessions/{id}` | **低置信须逐项处理**；候选**不自动绑定**；与已存字段冲突默认保留旧值 | 主体未匹配已审核 Party → **只提示去创建并审核**（不在确认动作里建 Party）；资产未匹配 → 提示去维护资产主档 |
| 5 | 提交确认 → 写入合同（**补录即生效**） | 解析确认页 | `POST /extraction-sessions/{id}/confirm` | **每写入字段须带字段来源**否则阻断；必填补齐；签订日期必填（domain-model §2、§5.2） | 校验失败 → 字段级报错 |
| 6 | 系统按租金/服务费条款**自动生成台账** | （后台） | — | 台账生成并**固化归属**（项目/产权方/运营方/资产，ADR-0011） | — |

## 关键 UX 约束（容易做错的地方）

- **解析只辅助、人工定夺**：高置信也不自动写入；确认页是「逐字段拍板」，不是「一键采用」。
- **推荐 ≠ 绑定**：未匹配只给「去创建/去维护」的路径提示，**不在确认动作里造 Party/Asset**。
- **会话即用即弃**：解析确认页**不存草稿、不可稍后继续**；确认/取消/失败后会话不留档。
- **补录即生效**：无提审/审核步骤——这是最小生命周期，**不是审批流**（ADR-0013）。别在 UI 上加「提交审核」。

## 状态

`草稿（录入/纠错中）` → `定稿生效`（生成台账）。后续纠错走 `生效 → 新纠错草稿 → 定稿`，原合同不反审核。
