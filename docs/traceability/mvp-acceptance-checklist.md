# 资产运营 v5 MVP 验收清单

## 1. 文档定位

本清单跟踪 [`docs/prd.md`](../prd.md) §9 的 G1–G7 与十个必测边界场景。产品范围和验收口径以 PRD 为准，实现与测试证据只在 [`requirements-trace.md`](requirements-trace.md) 中登记。

当前基线日期为 2026-10-23，S0 规格已收口并进入 V1 资产单元与合同链开发。以下状态以需求追踪矩阵中的真实代码与测试证据为准，不沿用 v4.0 的工程验收结论。

## 2. 一票否决门槛

| 门槛 | 验收标准 | 状态 | 所属切片 |
|---|---|---|---|
| G1 | 上游合同、资产单元、终端合同的覆盖关系唯一且可追溯，派生页面数字一致 | ⏳ 待实现 | V1 |
| G2 | 部分付款、到账、押金和撤销保留原事实，不覆盖累计值 | ⏳ 待实现 | V2 |
| G3 | 年度考核范围版本和月度报送快照可重放，历史月份不被当前台账改写 | ⏳ 待实现 | V3 |
| G4 | 资产单元拆合前后宗数和面积在生效日边界守恒，历史统计不回写 | ⏳ 待实现 | V1 |
| G5 | 导入错误时零写入，成功批次可追踪并可在规则允许时整批撤销 | ⏳ 待实现 | V4 |
| G6 | 403、上游缺失、租期越界、到期未处理和档案缺漏均明确可见 | ⏳ 待实现 | V1–V5 |
| G7 | 1280px 目标桌面、200% 缩放、320px 重排、键盘和减少动效场景通过 | ⏳ 待实现 | V1–V5 |

## 4. 完成规则

- V2 PR-0 先提供合同字段校验与同事务变更记录；G2、ACC-V5-006 / 007 仍待 PR-A 至 PR-C 的资金事实实现及验证，不因合同审计完成而推进为通过。
- 门槛状态只能在关联 REQ 具有真实代码路径、失败路径测试与验证结果后推进。
- 任一门槛失败均阻止 MVP 放量，不得以“仅前端展示”、“已知问题”或人工数据修正绕过。
- 验收过程发现缺陷时，在对应测试失败并完成修复后重验；不直接把状态改为通过。
- 状态变更时同步更新 [`requirements-trace.md`](requirements-trace.md) 与根目录 `CHANGELOG.md`。
