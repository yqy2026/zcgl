# API 契约

## 1. 文档定位

本文档描述当前目标态 API、权限和请求契约。产品需求见 `docs/prd.md`，领域对象见 `docs/specs/domain-model.md`，实现追踪见 `docs/traceability/requirements-trace.md`。

本文档只描述对外契约，不记录实现文件、测试文件或历史迁移过程。

## 2. 全局 API 规则

| 规则 | 契约 |
|---|---|
| 版本前缀 | 所有业务 API 统一使用 `/api/v1/*` |
| 认证 | 登录态使用 HttpOnly Cookie，会话支持刷新和退出 |
| 鉴权 | 写操作和受保护读操作必须鉴权 |
| 授权 | 使用 RBAC + ABAC，按钮和接口级动作均需授权 |
| 数据范围 | 业务查询按用户主体绑定自动过滤 |
| 项目主轴 | 项目端点承载资产、合同关系、台账摘要、风险和项目分析等运营视图 |
| 分析视图 | 分析和大屏端点使用 `view_mode` 指定 owner 或 manager 口径 |
| 搜索 | 搜索结果必须经过权限和数据范围过滤 |
| CSRF | 状态变更请求必须携带 CSRF token |
| 幂等 | 批量更新、补偿任务等关键写操作必须幂等 |
| 乐观锁 | 核心实体更新应使用版本冲突保护，冲突返回 409 |
| 删除 | 关键业务记录不提供用户侧物理删除入口 |

## 3. 请求范围与视图契约

### 3.1 BindingContext

常规业务端点不要求用户手动选择数据范围。系统根据用户绑定的主体自动过滤数据。

| 用户类型 | 常规查询行为 |
|---|---|
| 产权方绑定用户 | 只返回绑定产权方范围内数据 |
| 运营方绑定用户 | 只返回绑定运营方范围内数据 |
| 多绑定用户 | 返回各绑定范围的数据并集，按业务主键去重 |
| 管理员或审计用户 | 按授权查看全量或审计范围内数据 |

### 3.2 ViewMode

`view_mode` 只用于分析和大屏端点，不用于常规 CRUD。

| 参数 | 含义 |
|---|---|
| `view_mode=owner` | 产权方统计口径 |
| `view_mode=manager` | 运营方统计口径 |
| 不传 | 系统按用户绑定类型自动回落 |

`X-Perspective` HTTP header 已废弃，不作为当前契约。

## 4. 端点契约

### 4.1 认证与当前用户

| 能力 | 方法与路径 | 契约 |
|---|---|---|
| 登录 | `POST /api/v1/auth/login` | 校验凭据并写入会话 Cookie |
| 刷新 | `POST /api/v1/auth/refresh` | 刷新登录会话 |
| 退出 | `POST /api/v1/auth/logout` | 清理会话 |
| 当前用户 | `GET /api/v1/auth/me` | 返回当前用户、角色和能力摘要 |

### 4.2 用户、角色与权限

| 能力 | 方法与路径 | 契约 |
|---|---|---|
| 用户管理 | `/api/v1/auth/users/*` | 用户创建、编辑、启停用、密码重置 |
| 角色管理 | `/api/v1/roles/*` | 角色定义、权限勾选、角色分配 |
| 数据策略 | `/api/v1/auth/data-policies/*` | ABAC 策略包、模板和角色绑定管理 |

用户管理主契约使用多角色语义，支持单用户分配多个角色。多角色权限默认取允许权限并集；显式拒绝授权或拒绝数据策略优先于允许结论。

### 4.3 资产

| 能力 | 方法与路径 | 契约 |
|---|---|---|
| 资产列表 | `GET /api/v1/assets` | 支持分页、筛选、排序、搜索，并按主体范围过滤 |
| 资产详情 | `GET /api/v1/assets/{asset_id}` | 返回资产主数据和必要投影 |
| 创建资产 | `POST /api/v1/assets` | 创建草稿资产，需通过权限和数据范围校验 |
| 更新资产 | `PATCH /api/v1/assets/{asset_id}` | 审核态关键字段受控，需版本冲突保护 |
| 删除资产 | `DELETE /api/v1/assets/{asset_id}` | 逻辑删除，存在关联约束时拒绝 |
| 恢复资产 | `POST /api/v1/assets/{asset_id}/restore` | 恢复逻辑删除资产 |
| 批量操作 | `/api/v1/assets/batch-*` | 支持批量相关操作 |
| 导入资产 | `/api/v1/assets/import` | 支持模板校验和导入 |
| 资产附件 | `/api/v1/assets/{asset_id}/attachments/*` | 管理资产附件 |
| 资产产权证 | `/api/v1/assets/{asset_id}/property-certificates/*` | 资产详情内维护产权证，支持列表、详情、新增、编辑、附件、轻量在线预览、扫描件解析预填；产权证证号正式保存必填且全局唯一；同一本产权证覆盖多个资产时应维护既有产权证的资产关联，不得用相同证号新建第二条产权证；当当前资产上下文提交的证号已存在时，接口应返回既有产权证提示、既有产权证 ID、当前 `asset_ids`、既有产权证摘要和可在当前资产详情页执行的追加关联确认目标，不得创建新记录，也不得自动把当前资产追加进既有产权证；若本次请求包含扫描件附件，应把该附件作为既有产权证附件候选返回，默认建议随追加关联一并保留，但必须在确认载荷中显式确认后才写入既有产权证附件列表，用户取消时不得追加该附件；若既有产权证 `attachment_ids` 为空，确认载荷不得取消本次附件追加，否则应返回校验错误并拒绝追加资产关联；产权证必须至少关联一个既有资产，不允许保存为孤立证照记录；允许追加或移除资产关联，但更新后不得为空，删除最后一个资产关联应返回校验错误；产权证统一使用“附件”承载事实底座，必须至少保留一份附件；不区分“证照扫描件”和“其他附件”；上传或追加附件仅接受 PDF、JPG/JPEG、PNG，单个文件大小上限为 20MB，其他文件类型或超限文件应返回校验错误；附件上传或追加后不得自动创建解析会话或自动触发扫描件解析，解析辅助补录必须由用户显式发起；产权证解析会话创建请求只能引用当前产权证 `attachment_ids` 中的附件 ID，不得接收新文件上传载荷或临时文件作为解析输入；同一次操作允许多选上传多个附件，但接口应逐文件校验类型和大小，不合规文件不得进入附件列表，合规文件可继续保留；附件应支持轻量在线预览，PDF 可内嵌预览，JPG/PNG 可图片预览，预览权限跟随产权证查看权限，且不单独记录操作日志；下载是独立资料外流动作，下载按钮和下载接口必须校验产权证附件下载权限，不得仅凭产权证查看权限放行；MVP 不提供批注、旋转、裁剪、全文搜索或 OCR 原文高亮接口能力；预览失败时前端或接口只提示“预览失败，可下载查看”，不得阻断产权证保存、附件保留或扫描件解析；允许追加、替换、下载或删除附件，但删除最后一份附件应返回校验错误；下载附件应记录轻量操作日志，记录下载人、下载时间和附件，不要求提交下载原因，也不得记录下载来源页面、入口、客户端 IP 或设备信息，不得触发审批或告警；下载日志仅在系统操作日志/审计日志查询，产权证详情接口不默认返回下载记录；MVP 只支持单个附件下载，不提供多附件打包下载接口；系统操作日志查询产权证附件下载或变更记录时，应支持按产权证号筛选；附件文件名仅作为日志展示字段，不作为 MVP 筛选参数；替换附件时新附件取代旧附件，接口不保留被替换旧附件；删除附件时接口不要求提交删除原因，也不保存专门删除原因字段；上传或追加附件时可按同名或相同文件哈希生成疑似重复提示；接口和前端只需向用户提示“疑似重复附件”，不返回或展示具体命中依据；疑似重复附件默认不追加，用户显式选择追加即视为确认，不要求二次确认弹窗，重复提示不得作为保存阻断；MVP 不提供附件版本管理、替换审批、差异追踪接口、附件备注字段、附件维护来源字段、附件总容量配额、多附件打包下载、批量解析、批量确认或复杂上传队列治理，也不提供被替换旧附件保留、恢复能力或附件删除原因记录能力；如需追溯附件追加、替换、删除或下载动作，由通用操作日志承载；其中追加、替换、删除日志记录附件 ID、文件名、动作类型、操作人和操作时间，不记录操作原因，不保留被替换或删除的旧文件内容，也不做附件差异记录；同一本产权证可关联多个资产，且不区分主资产和附属资产；产权证权利人必须引用已审核 Party；正式保存硬门槛只包括证号全局唯一且非空、至少一个既有资产关联、至少一份附件、权利人引用已审核 Party（不含核验状态，`is_verified` 已删，见 ADR-0005）；任一关联资产当前主产权主体未包含在产权证权利人列表中时，仅对该资产返回或生成 `warning` 级数据质量风险提示，不阻断保存，也不影响同证下其他资产的风险判断；该风险只在资产详情产权证区域、产权证详情/编辑页和项目风险摘要展示，不进入全局搜索，不派生独立处置流程，不提供关闭、忽略或已处理动作；证照信息不完整按 `warning` 级风险提示，不得阻断资产维护、合同补录、台账生成或经营统计；证载面积、期限或限制信息缺失时，可返回轻量补录完整性提示，不返回任务、待办或审批对象，也不阻断保存；详情可返回 `field_sources` 供编辑或补录来源上下文按需查看 |
| 产权证扫描件解析 | `/api/v1/assets/{asset_id}/property-certificates/extraction-sessions/*` | 只能选择当前产权证附件列表中的附件发起解析，不支持在解析入口重新上传新文件；创建解析会话请求只能引用当前产权证 `attachment_ids` 中的附件 ID，不得接收新文件上传载荷或临时文件作为解析输入；需要解析新文件时，应先通过附件接口上传或追加为产权证附件，再由用户显式发起解析；同一产权证附件重新解析时，接口应生成新的临时解析结果，旧的未确认解析候选直接废弃，不返回候选版本对比，也不得覆盖已确认写入产权证主数据的字段；解析证号、权利人、坐落、面积、期限和限制信息，返回字段候选值、置信度、轻量来源证据、候选匹配、匹配提示和字段来源候选；若解析字段与当前产权证已保存字段冲突，接口应返回差异提示，已有字段默认保留，不得自动覆盖；只有用户逐字段确认或修正后的值才可在确认接口写入；必须人工确认后写入产权证；确认成功后前端自动返回产权证详情或编辑页并展示保存成功提示，不保留确认结果页；确认写入前必须有证号并通过全局唯一校验，且必须由用户显式选择至少一个既有资产；解析未取得证号时只能提示用户手工补齐后再确认，证号重复时应返回既有产权证 ID、既有关联资产、既有产权证摘要、维护提示和本次扫描件附件候选，引导用户在当前资产详情页显式确认追加当前资产，并默认勾选追加本次附件；若本次附件与既有附件同名或文件哈希相同，应提示“疑似重复附件”，不展示具体命中依据，并默认不勾选追加，用户显式选择追加即视为确认，不要求二次确认；用户取消附件追加时不得把本次附件写入既有产权证；但既有产权证没有任何附件时，不允许取消本次附件追加；确认接口不得创建重复证号产权证，也不得自动追加当前资产或附件；权利人候选仅限已审核 Party，资产候选仅限既有资产，候选不得自动绑定；权利人未匹配已审核 Party 时只返回提示，不直接创建 Party 或写入权利人关系；坐落未匹配既有资产时只返回提示，不直接创建或关联新资产，也不得保存为无资产关联的产权证；`should_create_new_asset` / `create_new_asset` 类载荷不属于 MVP 正式确认契约 |
| 租赁摘要 | `GET /api/v1/assets/{asset_id}/lease-summary` | 按上游、下游、委托、直租展示租赁情况 |
| 经营方历史 | `GET /api/v1/assets/{asset_id}/management-history` | 返回经营方变更历史 |
| 项目历史 | `GET /api/v1/assets/{asset_id}/project-history` | 返回项目关系历史 |
| 审核动作 | `/api/v1/assets/{asset_id}/submit-review|approve-review|reject-review|reverse-review|resubmit-review|withdraw-review`；`POST /api/v1/assets/batch-submit-review`；`POST /api/v1/assets/batch-approve-review` | 资产 `review_status` 两步生命周期流转；`approve-review` 按复核权限门控，**不限制审核人 ≠ 提交人**（持权限者均可，含提交人本人）；批量提交支持 `draft → pending`，批量确认支持 `pending → approved`，已在目标状态的资产幂等成功，状态不匹配逐项返回错误；资产不走路由审批流 |
| 审核日志 | `GET /api/v1/assets/{asset_id}/review-logs` | 返回资产审核日志 |

### 4.4 项目

| 能力 | 方法与路径 | 契约 |
|---|---|---|
| 项目列表 | `GET /api/v1/projects` | 支持分页、筛选、搜索，并按主体范围过滤 |
| 项目详情 | `GET /api/v1/projects/{project_id}` | 返回项目主数据 |
| 创建项目 | `POST /api/v1/projects` | 项目必须绑定运营管理方 |
| 更新项目 | `PATCH /api/v1/projects/{project_id}` | 更新项目主数据 |
| 删除项目 | `DELETE /api/v1/projects/{project_id}` | 逻辑删除 |
| 当前有效资产 | `GET /api/v1/projects/{project_id}/assets` | 返回项目当前有效资产汇总 |
| 合同关系 | `GET /api/v1/projects/{project_id}/contract-relations` | 返回项目下承租转租和代理运营合同关系投影 |
| 台账摘要 | `GET /api/v1/projects/{project_id}/ledger-summary` | 返回项目维度应收、应付、实收、实付、逾期摘要；承租模式上游合同计入应付，承租模式下游合同计入应收，代理模式服务费台账计入应收，直租租金不计入运营方自营应收 |

| 租户客户 | `GET /api/v1/projects/{project_id}/tenants` | 返回项目下终端租户、客户主体和合同数摘要 |
| 项目分析 | `GET /api/v1/projects/{project_id}/analytics` | 返回项目维度分析摘要，包含有效资产汇总、合同关系数、客户数、风险数、应收/应付/实收/实付/逾期、服务费摘要和月度收付款趋势，并按承租转租、代理运营分区返回关系数、覆盖资产数、主合同/终端合同数、客户数、收付款和风险数；代理直租租金不计入运营方自营应收 |

### 4.5 合同关系与合同

| 能力 | 方法与路径 | 契约 |
|---|---|---|
| 合同关系列表 | `GET /api/v1/contract-groups` | 辅助或内部入口，支持主体范围过滤、项目筛选和业务筛选；列表项返回所属项目名称和按合同角色聚合的数量 |
| 合同关系详情 | `GET /api/v1/contract-groups/{group_id}` | 返回合同关系投影、主体、资产和合同信息 |
| 创建合同关系 | `POST /api/v1/contract-groups` | 必须归属项目；同条合同关系只能选择一种经营模式 |
| 更新合同关系 | `PATCH /api/v1/contract-groups/{group_id}` | 更新合同关系主数据和关联信息 |
| 新增关系内合同 | `POST /api/v1/contract-groups/{group_id}/contracts` | 在既有合同关系内补录上游、下游、委托或直租合同；路径 `group_id` 必须与请求体一致 |
| 合同详情 | `GET /api/v1/contracts/{contract_id}` | 返回合同基表和类型明细；可返回 `field_sources` 供编辑或补录来源上下文按需查看，业务详情主视图不要求默认展示；签订日期、付款周期或备注类关键经营字段缺失时，可返回轻量补录完整性提示，不返回任务、待办或审批对象，也不阻断保存 |

| 合同扫描件附件 | `/api/v1/contracts/{contract_id}/attachments/*` | 上传、查询、下载和删除盖章扫描件；MVP 合同补录必须保留至少一份盖章扫描件 |
| 合同扫描件解析 | `/api/v1/contract-groups/{group_id}/contracts/extraction-sessions/*` | 上传合同扫描件后解析合同编号、主体、资产、期间、金额、租金或服务费条款，返回字段候选值、置信度、轻量来源证据、候选匹配、匹配提示和字段来源候选；必须人工确认后创建或更新合同补录；主体候选仅限已审核 Party，资产候选仅限既有资产，候选不得自动绑定；主体未匹配已审核 Party 时只返回提示，不直接创建 Party 或写入合同主体引用；资产未匹配既有资产时只返回提示，不直接创建或绑定新资产 |
| 合同作废 | `POST /api/v1/contracts/{contract_id}/void` | 补录错误或业务作废时保留历史记录；相关台账按规则作废（已收/部分已收条目需先人工处理；MVP 无红字冲销） |
| 审计日志 | `GET /api/v1/contracts/{contract_id}/audit-logs` | 返回合同补录、更正、作废和台账重算操作日志 |

MVP 不提供合同提审、审核通过、驳回、反审核或关系联审主契约。存量生命周期端点如仍存在，属于既有实现证据，不纳入当前 MVP 合同补录验收基线。

MVP 不提供续签端点。到期后继续合作按新合同补录流程创建合同关系和合同。上下游/委托/直租仅为收入/成本方向标记，MVP 不做主合同覆盖判定或覆盖风险。

### 4.10 扫描件解析辅助补录

| 能力 | 方法与路径 | 契约 |
|---|---|---|
| 创建解析会话 | `POST /api/v1/extraction-sessions` | 上传合同扫描件，或对当前产权证已有附件发起解析；当 `target_type=property_certificate` 时，请求只能引用当前产权证 `attachment_ids` 中的附件 ID，不得接收新文件上传载荷或临时文件作为解析输入；同一产权证附件重新解析时，新的临时会话结果取代旧的未确认候选，不保留候选版本对比，也不影响已确认写入目标对象的字段；不提供解析草稿创建或恢复参数；指定 `target_type=contract|property_certificate` 和可选上下文，返回临时会话 ID |
| 查询解析状态 | `GET /api/v1/extraction-sessions/{session_id}` | 返回临时解析状态、候选字段、字段置信度、字段级轻量来源证据、候选匹配列表、低置信字段标记、字段来源候选、匹配提示、解析候选与已保存字段的差异提示、建议补全字段和错误信息；建议补全字段仅限目标对象字段契约内的少量经营关键字段，合同为签订日期、付款周期、备注类关键经营字段，产权证为证载面积、期限、限制信息；不得返回目标对象全部可选字段作为确认页表单；建议补全字段属于质量提示，不作为确认保存硬校验，保存后仍为空时只能形成补录完整性提示；字段级轻量来源证据仅用于确认页核对，确认、取消、失败或放弃后不得作为长期记录返回；产权证解析失败或低置信字段较多时，仅返回用于当前解析确认页和产权证编辑页展示的提示，不返回待办、任务或待处理工单对象；低置信字段必须在确认页逐项处理，处理方式只能是确认候选值、修正为手工值，或在非必填字段上显式选择暂不填写或留空；差异提示不得导致自动覆盖已保存字段；MVP 不返回“一键采用全部高置信无冲突字段”或批量采纳动作 |
| 确认解析结果 | `POST /api/v1/extraction-sessions/{session_id}/confirm` | 用户提交确认、修正、手工补齐或明确留空后的载荷、`confirmed_field_keys` 和 `field_sources`；`field_sources` 仅写入目标对象的最终字段来源快照，取值为 `manual`、`ocr_prefill_confirmed` 或 `ocr_prefill_corrected`，不承载复杂版本 diff、页码、文本片段或截图区域，后续仅供编辑或补录来源上下文按需查看；非必填解析字段允许用户选择暂不填写或留空，空值的 `field_sources` 记为 `manual`；解析未识别但用户在确认页手工补齐的目标对象字段，其 `field_sources` 记为 `manual`；建议补全字段不填写不阻断确认保存，空值的 `field_sources` 仍记为 `manual`，确认后只可由当前目标对象派生补录完整性提示，不得生成任务、待办或审批；确认载荷中每个写入目标对象的字段都必须有对应 `field_sources`，来源缺失应返回校验错误并阻断确认保存；普通非解析编辑接口不适用该解析确认强校验，缺失来源时可由服务端默认补 `manual`；必填字段不得以留空通过确认保存；确认载荷和 `confirmed_field_keys` 只能包含目标对象字段契约内字段，提交字段契约外临时字段时应返回校验错误；确认接口不接收 `accept_all`、`accept_all_high_confidence` 或类似一键采纳/批量采纳载荷，`confirmed_field_keys` 必须表达字段级确认；服务端再次校验主体、资产、证号必填与全局唯一性、附件、低置信字段确认记录、字段来源快照和必填字段后写入目标对象；低置信字段必须在确认载荷中处于已确认候选值、已修正为手工值，或非必填字段已显式留空三种状态之一，未处理的低置信字段应返回校验错误；解析候选与已保存字段冲突时不得自动覆盖，未包含在确认载荷或 `confirmed_field_keys` 中的冲突候选不得写入，也不得改变已保存字段的 `field_sources`；候选匹配结果不得被服务端自动采纳，主体或权利人引用必须是用户显式选择的已审核 Party，资产引用必须是用户显式选择的既有资产；合同必须保留盖章扫描件，产权证必须至少保留一份附件且至少关联一个既有资产；产权证附件仅接受 PDF、JPG/JPEG、PNG 且单个文件大小不得超过 20MB；未匹配、未显式选择、附件缺失、证号缺失、产权证未选择既有资产、低置信字段未确认、来源缺失或必填字段留空时返回校验错误或待处理提示；产权证证号重复时返回既有产权证冲突或维护提示，附带既有产权证 ID、摘要、当前关联资产信息、当前资产详情页内追加确认目标和本次扫描件附件候选，不创建新记录且不自动追加资产或附件；只有用户在确认载荷中选择追加本次附件时，才可把该附件写入既有产权证；既有产权证当前没有任何附件且确认载荷取消本次附件追加时，应返回附件硬门槛校验错误，不得完成资产关联追加；确认成功后清理解析会话，不保留会话档案、页码、文本片段或截图区域等字段级来源证据；产权证解析确认成功后前端自动返回产权证详情或编辑页并展示保存成功提示，不提供确认结果页查询或停留入口 |
| 取消解析会话 | `POST /api/v1/extraction-sessions/{session_id}/cancel` | 取消未确认会话，不写入业务主数据，并清理临时会话；不保留草稿，也不提供稍后继续确认入口 |

抽取失败支持手动重试；AI/OCR 抽取结果确认前可人工修正；单文件超时进入失败队列。解析会话仅作为当前补录过程的临时工作区，确认、取消、失败或放弃后不作为长期记录保留；API 不提供解析会话历史档案查询能力，也不提供解析确认草稿保存、草稿恢复或稍后继续确认能力。产权证解析确认成功后前端自动返回产权证详情或编辑页并展示保存成功提示，不提供确认结果页查询或停留入口。目标对象不保存解析工具、模型、供应商、置信度、确认时间、页码、文本片段或截图区域等解析元信息和字段级来源证据。解析失败、超时或低置信度不得阻断用户完全手工补录合同或产权证，但低置信字段不得静默进入最终载荷，必须由用户逐项处理；处理方式只能是确认候选值、修正为手工值，或在非必填字段上显式选择暂不填写或留空；未处理的低置信字段不得直接提交确认；非必填解析字段可由用户确认留空并以 `manual` 记录空值来源，必填字段必须补齐后才能确认保存。用户可在确认页补齐解析未识别出的目标对象字段，字段来源记为 `manual`；API 应拒绝目标对象字段契约外的临时字段。产权证解析失败或低置信字段较多时，API 不创建或返回审批待办、系统任务、补录任务或待处理工单，只返回当前解析确认页和产权证编辑页可展示的提示，并允许用户手工补录或重新解析。同一产权证附件重新解析时，API 不保留旧的未确认解析候选或候选版本对比，已确认写入主数据的字段保持不变。MVP 不提供一键采用全部高置信无冲突字段或批量采纳解析候选，所有解析候选均按字段确认。查询解析状态时应为关键字段返回轻量来源证据，至少包含页码、文本片段或截图区域之一，用于确认页辅助核对；也可返回少量建议补全字段，但不得将合同或产权证全部可选字段返回为确认页编辑项，建议字段不填写也不得阻断确认保存；建议字段保存后仍为空时，只由目标对象详情/编辑上下文或项目风险摘要派生补录完整性提示，不返回任务、待办或审批对象。解析候选与已保存字段冲突时应返回差异提示，已有字段默认保留，不自动覆盖；MVP 不要求返回全文标注编辑数据，也不保存来源证据长期历史。解析结果可以返回候选匹配列表，但只允许推荐已审核 Party 或既有 Asset；即使候选高置信，也不得自动写入主体、权利人或资产引用。确认保存时必须提交最终字段来源快照，并写入目标对象，用于区分手工录入、解析预填确认和解析预填修正；确认载荷中写入目标对象的字段缺少 `field_sources` 时必须校验失败，普通非解析编辑可由服务端对缺失来源默认补 `manual`；MVP 不要求 API 返回逐次编辑版本差异，业务详情主视图也不要求默认展示字段来源。扫描件解析不得在确认动作中直接创建 Party 或 Asset；合同主体和产权证权利人必须由用户选择已审核 Party 后才能写入，合同和产权证关联资产必须由用户选择既有资产后才能写入；产权证不得保存为无资产关联的孤立证照。合同补录必须保留至少一份盖章扫描件，产权证必须至少保留一份附件；产权证解析入口只能选择当前产权证附件列表中的附件发起解析，不支持在解析入口重新上传新文件；需要解析新文件时必须先通过附件接口上传或追加；产权证附件仅接受 PDF、JPG/JPEG、PNG，单个文件大小上限为 20MB，同一次操作可多选上传多个附件并逐文件校验；多附件上传不等同于批量解析、批量确认或复杂上传队列。任何解析结果不得绕过人工确认直接写入合同或产权证主数据，也不得自动覆盖已保存字段。

OCR/AI 未识别但由用户在解析确认页手工补齐的目标对象字段，确认页可显示手工补齐或来源标记；确认接口仍只写入 `field_sources=manual`，纯手工录入和解析未识别后手工补齐不得拆成不同来源枚举，也不得新增 `manual_after_ocr_miss` 或类似子类型，不长期留存字段证据。详情接口可在编辑或补录来源上下文返回该来源信息，业务详情主视图不要求默认展示。

| 业务规则冲突 | 返回明确业务错误和可读原因 |
| 校验失败 | 返回字段级校验信息 |
| 重复幂等请求 | 不重复创建记录，不重复产生副作用 |

## 6. Out of Scope API

以下能力可存在代码骨架或历史入口，但不进入 MVP API 验收：

| 能力 | 说明 |
|---|---|
| 权属方管理 | 路由和用户可见入口已冻结，待补齐正式需求后重新激活 |
| 通用 BPM 引擎 | MVP 不建设通用审批流引擎 |
| 财务总账和支付结算 | 不属于当前产品边界 |
| 扫描件批量解析 | 批量上传、批量解析、批量确认或批量落库不作为 MVP API 契约；如保留存量入口，不进入用户主路径和验收范围 |
| 用户侧物理删除 | 关键业务记录不提供物理删除入口 |

## 7. 维护规则

- 新增 API 必须同步本文档。
- API 字段语义变更必须同步 `docs/specs/domain-model.md`。
- API 实现状态和证据变化只同步 `docs/traceability/requirements-trace.md`。
- 本文档不得记录实现文件路径、测试文件路径或历史迁移过程。
