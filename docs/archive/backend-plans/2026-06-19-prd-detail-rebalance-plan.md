## Problem

PRD（`docs/prd.md`，305 行 / 50KB）详略失衡，根因不是行数（2026-04-27 立的 400–600 行目标按行数仍达标），而是 grill 之后**单格密度爆炸 + 同一主题反复沉积**：

1. **抽象层级失控**：PRD §1 自立规矩「只写产品要做什么/为什么/做到什么算完成，字段·状态机·API 契约由其他文档承载」，但 REQ-AST-005（line 144）/REQ-DOC-001（line 193）写满实现级细节——`20MB`、`PDF/JPG/PNG` 白名单、下载日志字段、`field_source` 枚举值、同名/哈希去重提示。
2. **解析/附件规则复制 5 处**：同一套「人工确认才落库 / 不自动绑定 Party·Asset / 低置信逐项处理 / 不存草稿 / 失败不阻断 / 建议补全不阻断 / 风险派生不可手工关闭」在 §6.3（126–128）、REQ-AST-005（144）、REQ-RNT-003（160）、REQ-DOC-001（193）、§9 验收（253–272）各写一遍。任一处改口径要同步 5 处，必然漂移——而 §3.2 唯一成功指标恰是「口径一致性问题 ≤2/月」，文档结构本身在制造口径风险。
3. **详略与业务价值倒挂**：产权证附件管理（资产详情内一个子能力）文字量 > 租赁/合同域（7.3）+ 客户域（7.4）+ 分析域之和；而系统核心价值（承租/代理收入派生、台账生成、客户双指标）反而相对简略。
4. **§9 退化成需求复述**：253–272 行把 REQ-AST-005/REQ-DOC-001 整段二次声明，已非「可测用例断言」。
5. **落点缺失**：`domain-model.md` 对象清单为 4.1 Asset … 4.19 PartyContact，**无 产权证 / 附件 / 字段来源 对象**（整簇词命中≈0）——这些规则现在只活在 PRD，没有 spec 家可去。
6. **守卫盲区**：`make docs-lint`（`scripts/check_requirements_authority.py`）只挡 `代码证据`/`backend/src/` 等路径 token，不挡 `20MB`/枚举值等字段级 token，bloat 因此绕过守卫回灌。

## Principles（沿用 2026-04-27）

1. 最终态/过程态分离，产品事实/工程证据分离。
2. **一个事实只放一个地方**（本方案核心）。
3. 两个高度各自权威：PRD 写**产品级不变量**（PM/QA 读的 bullet），domain-model/api-contract 写**机制细节**（枚举、阈值、字段来源值）。
4. 先搬迁建落点再瘦身，不重新发明需求。
5. REQ-* 编号与 ADR-0001~0020 引用一个不动。
