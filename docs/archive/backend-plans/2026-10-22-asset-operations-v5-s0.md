# 资产运营 v5 S0 规格收口与实施计划

> **状态**：✅ 已完成
> **日期**：2026-10-22
> **产品基线**：`frontend/prototype/asset-ops-v5.html`
> **架构裁决**：`docs/architecture/ADR-0028-asset-operations-v5-workbench-boundary.md`

## 1. 目标

将资产运营 v5 从可点击设计稿收口为可编码、可测试、可追踪的产品基线，并在规格稳定后按纵向业务切片实施。S0 期间不新增业务 ORM、公开 API 或正式页面。

## 2. 已确认边界

- 业务工作台只有资产管理岗；系统管理角色不进入业务导航。
- 本系统从已签合同和外部完成的收付款事实开始，不建设合同 BPM、招商意向、底价审批、生效检查、银行匹配、发票、催收、产权方门户或领导视角。
- 上游合同、资产单元、终端合同及追加事实是业务事实源；本月、台账、报送和档案是投影。
- 项目只作为管理归属标签，任何宗数、面积、出租状态、租金和报送统计都从资产单元或合同事实逐行汇总。
- 不保留 v4.0 双写入口、旧导航或第二套统计口径。

## 4. 实施切片

每个切片均采用测试先行，先覆盖不变量和失败路径，再实现后端分层与前端页面。

### V1：资产单元与合同链

- 资产单元列表、详情、空置原因和租赁时间轴。
- 上游合同、终端合同、合同覆盖单元与版本链。
- 出租状态、到期天数、上游缺失和租期越界风险派生。
- 验收终点：同一份终端合同可覆盖多个单元，单元仍逐宗计数；历史月份不因当前关系修改而变化。

### V2：租金、押金与委托管理费

- 承租租金应付、终端租金应收、产权方到账报告和追加登记/撤销。
- 押金应收未收、应退未退、应收回。
- 产权方实收明细、管理费试算、盖章对账确认。
- 验收终点：部分付款、跨月欠款、撤销和已确认对账均不覆盖原事实。

### V3：考核范围与月度报送

- 年度考核范围草稿、版本、年中新增确认。
- 月末出租率草稿、门槛校验、提交快照、撤回和差异提示。
- 验收终点：已报月份保持不可变；当前台账变更只能产生差异提示或后继快照。

### V4：档案与批量导入

- 产权证、合同扫描件、交接书和对账单矩阵。
- 新增/更新两种导入模式、逐行差异、原子提交和七日内整批撤销。
- 验收终点：导入失败不产生部分写入，撤销不改写已报送快照。

### V5：本月工作台

- 从 V1–V4 投影本月截止事项、随时处理事项、进度和目标深链。
- 验收终点：完成数、金额、档案缺口和报送门槛与各事实页一致，无独立可写状态。

## 5. 强制不变量

1. 派生投影不得成为事实源。
2. 出租状态不可手改；以统计月最后一天的有效终端合同派生。
3. 一份终端合同可覆盖多个资产单元，但每个单元独立计宗。
4. 报送快照和当时考核范围版本一同锁定，后续台账变更不回写。
5. 撤销只追加原因和反向事实，不删除原付款、到账、终止、退出、报送或导入记录。
6. 上游缺失和租期越界必须显式暴露，不以吞错或静默修正掩盖。
7. 403 与空列表严格区分；无权限不得伪装为无数据。
8. 写请求携带幂等键和期望版本；过期预览或并发修改返回稳定 409。

## 6. 设计与可访问性门槛

- 1280px 是业务桌面目标宽度，不得把 `min-width: 1280px` 直接复制到正式页面；在 200% 缩放下必须可达全部内容和操作。
- 所有控件有可访问名称、可见标签和 `:focus-visible`；键盘可以完成全部流程。
- 加载骨架在 `prefers-reduced-motion: reduce` 下停止循环动画。
- 正式实现使用 Ant Design、CSS token 和现有 React Query/路由/权限框架，不复制原型内联样式或本地状态机。
