## 1. 目标与非目标

V2 在 V1 的“上游合同 → 资产单元 → 终端合同”事实链上，建立三条资金事实，并补齐它们依赖的合同修改规则与变更记录：

1. **租金义务与登记**：由合同租金阶段生成承租应付、转租应收、直签产权方应报到账三类义务；合同期限、租金阶段或生命周期变化时重排未锁定义务；外部付款 / 到账以追加记录登记，支持部分完成、跨月结转与有原因撤销；租金阶段在录入和续签时一并核对，确认后可更正（往月已有阶段不改，往月缺口可补录）；提前退租可登记补收免租。
2. **押金**：承租合同和终端合同各一条押金条目，跟踪约定与实际持有，区分应收未收、应付未付、应退未退、应收回四类；续签时押金转入后继合同；合同结束后转租押金可抵扣欠租，终止时默认自动抵扣截至当月的欠租；不退还的部分登记为押金扣除。委托管理协议不约定保证金，也没有租金阶段。
3. **委托管理费对账**：基于产权方实际到账逐户试算，每产权方每月一张对账单，截止日后未收余额自动顺延，按月份顺序盖章确认后锁定，更正走后继单。
4. **合同修补与变更记录**：合同级付款周期 / 付款日确认后只读；合同修改按合同类型校验字段；落地变更记录，覆盖 V2 命令和 V1 合同命令。

V2 **不实现**：本月工作台（V5，仅保留义务 / 押金 / 对账状态的可查询投影）、考核范围与报送（V3）、档案矩阵与导入（V4，盖章件与凭证复用 V1 已有 Attachment 存储，不建档案矩阵）、资产单元命令的变更记录（V3 补齐）、银行流水认领、发票、催收、付款指令（PRD §4.2 Out of Scope）。

## 6. 数据与切换原则

1. V2 以新增表与追加记录为主；对 V1 已有表与接口的改变：委托管理协议押金必须为 0（先检查、后加约束，存在非 0 行时迁移失败并输出清单，由人工处理）、合同级付款字段改为只读、租金阶段表增加被替换标记，以及合同确认、修改、续签、终止 / 退出的事务里增加义务重排、押金与变更记录写入。
2. 义务、押金条目（只为承租合同和终端合同）与对账单回填走一次性幂等脚本，先 dry-run 后执行，输出合同数、义务数、押金条目数、对账单数与金额合计供核对。
3. V1 界面建的合同都没有租金阶段，回填只会得到 `RENT_SCHEDULE_GAP`。目标环境切换时，dry-run 输出缺阶段合同清单，逐份用租金阶段更正补录（D-25 允许补录往月）；补录完成前这些合同不出账。
4. 不读取、不转换旧 `contract_ledger_entries` / `operational_payment_flows` / `service_fee_ledgers`；目标环境若需要历史付款、押金或对账事实，走 V4 导入或人工底稿，不在 V2 做语义迁移。
5. 不建立“新表无数据时回落旧表”的兼容分支；旧表删除仍归旧域清理专项。
6. 金额全程 `Decimal`，日期全程 `Asia/Shanghai` 业务日；任何派生值（状态、余额、合计、押金方向、管理费金额）不入写模型。

## 8. 风险

| 风险 | 缓解 |
|---|---|
| 重排与生命周期命令、阶段更正或登记撤销并发，导致重复或遗漏义务 | 共用资产单元 / 合同 / 义务 / 押金条目行锁顺序；`period_start` 唯一约束兜底；重排纯函数可重复执行 |

| 锁定义务与合同条款不一致长期滞留 | `RENT_LEDGER_PLAN_MISMATCH` 在台账格子、合同详情和预览可见；V5 规划本月页时决定是否增加对应事项类型（领域模型 §4.30 目前没有） |
