# V4 产权证档案上传与替换验收

日期：2026-11-03。范围为 V4-1 产权证档案切片，当前产品契约见 [PRD](../../prd.md)、[领域规格](../../specs/domain-model.md)、[API 契约](../../specs/api-contract.md) 和 [实现追踪](../../traceability/requirements-trace.md)。本记录是本地工作树证据，不代表已合并、部署或完成整个 V4。

## 交付

- 新增统一档案上传与替换 POST，返回档案 ID 和版本展示字段；只接受单个产权证扫描文件。
- 入口要求 `asset_ops:archive`，每请求解析当前范围；暂存前鉴权，取得产权证锁后再查可见物业已生效关联。权利人匹配本身不能授予文件访问资格。
- 复用既有文件生命周期、哈希去重、证照锁及版本登记；重复内容和陈旧前驱返回 409，历史文件保留。用户主体绑定采用请求时解析的范围快照，不宣称锁住全部授权状态。
- 移除无生产调用方的旧产权证附件全组路由及闲置前端服务；新入口负责列表、下载及维护，内部解析确认仍共用版本登记。
- 详情档案抽屉增加上传及现行文件替换，档案权限与物业维护权限分开。关闭自动重试；重开及陈旧冲突刷新版本，并提供手动重载。
- 权限种子补入 `asset_ops:archive`，未运行种子脚本改写用户数据库。

## 失败用例与复核

旧路由退役守卫先验证六项失败，再在移除路由后六项通过。新服务先以无效范围写入回归复现失败，再补上传/替换实现；前端新增上传服务与交互回归亦先失败后修复。

后端、前端各派发一个实现子任务，第三个只读复核子任务检查授权、版本链、multipart 和页面状态。复核指出全局 React Query 自动重试会重放写入，以及全局缓存配置使重开抽屉仍显示旧版本；两项均采纳，新增三个使用实际全局默认值的回归先失败后通过。

首轮后端全量回归有一项权限种子覆盖失败，补齐档案权限后全量复跑通过。首次浏览器窄屏边界检查发生在抽屉滑入中间，改为等待实际控件边界稳定后重新验证；没有以此修改生产布局或跳过窄屏场景。

## 余项与建议回归

本机无 make，未运行完整 `make check`、覆盖率门禁和 OCR 模型运行时检查；本轮范围不涉及 OCR 提取行为。档案完成率、矩阵、人工配对、其他档案对象和导入仍待后续实施；对账分母、补充/交接依据及批次撤销截止时刻仍未裁决，未用默认值实现。
