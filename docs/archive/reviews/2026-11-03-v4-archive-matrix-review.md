# V4 当前档案矩阵检查点

本轮接入当前在管物业的档案完成率、按物业矩阵、搜索/项目筛选及分页、缺件详情链接和只读菜单。契约见 [API](../../specs/api-contract.md#512-档案) 与 [统计口径](../../specs/domain-model.md#69-档案完成率)。没有新增事实模型或迁移，投影不反向写业务记录。

总览按业务对象去重，物业矩阵显示共享状态；无证照关联的物业单列，不推造一本缺证。合同和已确认对账引用已有扫描件事实并校验附件归属。交接书依据有效未撤销事件，父合同结束不消除交接依据。补充协议因登记清单尚未实现，明确显示待接入，数量与比率均为 null。零分母显示不适用，不标为 100%。

后端与前端分工实现，独立只读复核发现历史协议的已确认对账混入当前范围；已采纳并补充测试，新增回归先 3 项失败，修复为当前有效管理协议及当前有效覆盖后，相关服务测试 9 项通过。前端将项目、搜索及分页写入 URL，防止刷新或响应式重新挂载时丢失筛选。

真实 Chromium 已通过 8 组检查：真实登录、共享证照去重、未关联计数、分页总量、搜索结果、缺件链接、320/640/1440px 布局和零脚本异常。隔离验收库包含 23 个当前可见物业，共享证照与缺件证照各一本，范围外/未来/结束物业不进入当前结果。截图与结果保存在本机 `C:/Users/y/.codex/visualizations/2026/10/30/01a18b15-7102-7520-8820-de5f31ab8462/v4-matrix/`。

验证环境一度因 Docker 服务关闭而无法连接隔离 PostgreSQL/Redis，已恢复自有验证容器后重跑浏览器；该故障没有被计为验证通过。后端服务 9 项、真实 PostgreSQL/HTTP 1 项、前端新增 6 项通过。源码 Ruff、后端定向 mypy（4 文件）、前端 app 类型与定向 lint、文档门禁和 UI guard 通过。前端 forks 执行方式曾停在 RUN 未返回，停止自有进程后以 threads 单 worker 重跑，6 项正常结束。类型检查发现混合模型集合被推断为 Base，已改精确联合类型及显式查询，不使用 ignore。没有重复全量 make check 或覆盖率门禁。
