# 土地物业资产运营管理系统 PRD

## 1. 文档定位

本文档描述土地物业资产运营管理系统的产品目标态，是业务、产品、设计、研发和验收共同使用的产品需求基线。

本文档只回答“产品要做什么、为什么做、做到什么算完成”。字段、状态机、API 契约、代码实现证据、历史决策过程分别由其他文档承载。

## 2. 背景与问题

土地/物业资产运营当前存在资产台账分散、合同链路割裂、证照与主体信息分散、统计口径不统一等问题。现实经营同时包含承租模式与代理模式，跨产权方、运营方、终端客户的业务关系复杂，依赖人工台账和线下口径容易造成漏记、重复统计和权限风险。

系统目标是建设统一资产运营平台，以项目为普通用户的主工作对象，覆盖项目、资产、合同关系、合同、台账、客户、分析和权限，支撑运营管理闭环。

## 3. 产品目标

### 3.1 MVP 一票否决目标

| 目标 | 验收含义 |
|---|---|
| 资产清晰可见 | 资产页和项目页可展示资产基本信息、租赁情况、客户摘要 |
| 项目合同关系可用 | 承租模式与代理模式都可在项目下建模，且单条合同关系内模式不混用 |
| 合同补录和台账可追踪 | 盖章扫描件上传、必要经营字段补录、台账生成和更正均有留痕 |
| 经营统计口径可用 | 支持总收入、自营租金收入、代理服务费收入、客户双指标 |

### 3.2 上线后三个月成功指标

| 指标 | 目标值 | 认定规则 |
|---|---|---|
| 关键报表口径一致性问题 | <= 2 个/月 | 口径类缺陷以 issue 标签（`口径问题`）登记，按「确认为真实口径不一致的缺陷数」逐月计数，由产品负责人月度复盘认定；纯人工流程，不建系统功能或报表 |

> 原「资产台账完整率 >= 98%」与「核心流程平均处理时长下降 >= 40%」已删除：前者无口径定义，与已删的台账覆盖率同构（数据完整性由导入模板校验、资产两步确认、补录完整性提示机制保障，不靠事后指标）；后者无线下基线，不可证伪。MVP 的核心成功标准是 §3.1 一票否决目标与 §9 验收门槛。

### 4.1 In Scope

| 范围 | 能力 |

| 资产管理 | 列表、详情、新增、编辑、删除/恢复、导入、附件 |
| 项目管理 | 项目与资产关系管理、项目运营台账、项目汇总视图 |
| 租赁管理 | 承租模式、代理模式、合同关系、盖章扫描件上传、解析预填、人工确认补录、台账生成与维护、台账实收登记 |
| 客户管理 | 客户增强信息、历史签约、风险标签、账期偏好 |
| 搜索能力 | 全局搜索入口与模块内搜索并存 |
| 权限体系 | 登录、会话刷新、角色权限配置、关键操作鉴权、基于主体绑定的数据范围自动注入 |
| 数据分析 | 概览、趋势、分布、收入拆分、客户双指标 |
| 文档处理 | 合同和产权证单件扫描件上传、OCR/AI 解析、预填、人工确认、重试和超时处理 |
| 产权证管理 | 作为资产详情内能力维护资产证照信息、产权方权利人、附件、解析预填；产权证数据质量风险只剩客观两类（信息不完整、权利人与资产主产权主体不一致），不作为审批或业务门禁。MVP 不做核验状态（`is_verified` 已删，见 ADR-0005） |
| 消息通知 | 站内通知中心，合同即将到期/已到期、付款到期、付款逾期、系统通知五类提醒；企业微信可选推送。通知是提醒不是工单（见 REQ-NTF-001） |

### 4.2 Out of Scope

| 范围 | 说明 |
|---|---|
| 通用 BPM 审批流引擎 | MVP 不建设通用流程引擎 |
| 财务总账、税票、支付结算 | 只做运营台账和统计，不做财务总账系统。「支付结算」指对接网银/支付通道的实际收付款、对账流水和发票税票，**不做**；但在台账上手工登记实收结果（见 §4.1 台账实收登记）不属于此项，属于 In Scope，二者须区分 |

| 高级 BI 建模 | 不做自定义分析语言和高级 BI 建模 |

| 合同审批和状态门禁 | 全部合同只做盖章扫描件上传和必要字段补录，不做合同提审、审核、生效、反审核或状态流转限制 |
| 权属方管理 | 旧独立 Ownership 管理模块不纳入正式需求基线和功能验收；产权方统一由 Party 主档表达 |
| 扫描件批量解析 | 合同和产权证批量上传、批量解析、批量确认或批量落库不纳入 MVP；MVP 仅验收单件扫描件解析辅助补录 |
| 解析候选批量采纳 | MVP 不提供“一键采用全部高置信无冲突字段”或批量采纳解析候选；解析确认按字段逐项确认或修正 |
| 催缴管理 | 不建催缴工单、催缴状态机或催缴成功率统计；逾期处理依靠台账逾期查询和台账实收登记闭环（见 REQ-RNT-006）。如催收量增长需要分派与跟踪，按 vNext 另行设计（见 ADR-0006） |

## 5. 角色、权限与数据范围

系统采用角色、绑定、视图三维正交模型。

| 维度 | 解决的问题 | 规则 |
|---|---|---|
| 角色 | 用户能做什么操作 | 基于 RBAC 与 ABAC 控制按钮和接口级动作 |
| 绑定 | 用户能看哪批数据 | 基于用户绑定的产权方或运营方主体自动过滤 |
| 视图 | 同一数据用什么经营口径解读 | 仅分析和大屏使用 owner / manager 口径 |

核心规则：

- 用户权限 = 角色可执行动作与主体绑定数据范围的交集。
- 多角色权限默认取允许权限并集；如命中显式拒绝授权或拒绝数据策略，则拒绝优先。
- 权限管理员只可管理用户、角色、权限配置，不可查看业务数据。
- 多绑定用户在常规列表中展示数据并集，并按业务实体主键去重。
- 分析和大屏不能混合产权方口径与运营方口径，必须按视图口径展示。
- 管理员和审计类用户可按授权查看全量数据。

## 6. 核心业务口径

### 6.1 客户定义

客户不是固定身份，而是合同对方主体。同一主体可在不同合同中扮演不同角色。

客户列表以主体为唯一行，通过角色标签展示其在合同中的角色。历史合同保留签署时主体名称快照，不因主档后续变更而追溯覆盖。

### 6.2 经营模式

系统支持两种经营模式：

| 模式 | 结构 | 收入口径 |
|---|---|---|
| 承租模式 | 运营方从产权方承租，再向终端客户转租 | 自营租金收入 |
| 代理模式 | 产权方与终端客户直租，运营方提供代理管理 | 代理服务费收入 |

单条合同关系只能对应一种经营模式，不允许在同一合同关系内混用承租和代理。一个项目可以同时承载承租模式和代理模式，但展示和统计必须按模式分区。

### 6.3 合同关系分类

| 分类 | 所属模式 | 含义 |
|---|---|---|
| 上游 | 承租模式 | 产权方与运营方之间的内部入约合同 |
| 下游 | 承租模式 | 运营方与终端客户之间的对外出约合同 |
| 委托 | 代理模式 | 产权方与运营方之间的委托管理协议 |
| 直租 | 代理模式 | 产权方与终端客户之间的对外出约合同 |

上下游/委托/直租仅是**收入与成本的方向标记**：下游/直租租金计入收入，上游租金计入成本，代理直租派生服务费收入——全部按每份合同的分类计算，不做合同对合同的逐对配对，也不做"主合同覆盖"判定。盈亏沿"合同 → 资产 → 项目"归属链汇总，当前成本/当前收益只在项目级（及合同关系级）呈现，不分摊到资产级。

MVP 中全部合同只做盖章扫描件上传和必要经营字段补录，不做合同审批、提审、生效或反审核限制。系统允许任意类型合同按实际资料到达顺序补录；每份合同必须保留至少一份盖章扫描件作为合同事实底座。扫描件可经 OCR/AI 解析后预填关键字段，但必须由用户人工确认或修正后写入。解析会话仅作为临时工作区，确认、取消、失败或放弃后不作为长期记录保留；解析确认页不支持保存草稿或稍后继续确认；产权证解析确认成功后自动返回产权证详情或编辑页并展示保存成功提示，不保留确认结果页；长期事实以合同或产权证主数据、附件和字段来源快照为准，不记录解析工具、模型、供应商、置信度或确认时间等解析元信息。解析失败、超时或低置信度时，用户仍可完全手工补录并继续；产权证解析失败或低置信字段较多时，不生成待办或任务，只在当前解析确认页和产权证编辑页提示，用户可手工补录或重新解析；同一产权证附件重新解析时，旧的未确认解析候选直接废弃，不保留候选版本对比，已确认写入主数据的字段不受影响；低置信字段必须高亮并由用户逐项处理，处理方式只能是确认候选值、修正为手工值，或在非必填字段上显式选择暂不填写或留空；未处理的低置信字段不得直接提交确认，也不能静默带入最终补录。非必填解析字段允许用户选择暂不填写或留空，保存时按 `manual` 记录空值来源，必填字段仍必须补齐后才能确认保存。用户可在确认页补齐解析未识别出的目标对象字段，字段来源记为 `manual`；但不得新增不属于目标对象字段契约的临时字段。确认页需为关键字段展示轻量来源证据，包括页码、文本片段或截图区域之一，用于辅助人工核对原件；MVP 不做复杂全文标注编辑器。保存时记录字段来源快照，区分 `manual`、`ocr_prefill_confirmed` 和 `ocr_prefill_corrected`，不要求复杂版本差异追踪；解析确认保存时，提交的每个目标字段值都必须有对应字段来源，来源缺失应阻断确认保存；普通非解析编辑可由服务端对缺失来源字段默认补 `manual`。字段来源仅在编辑或补录来源上下文按需查看，不默认占用合同或产权证业务详情主视图。解析出的合同主体名称、权利人名称、资产地址或坐落可用于推荐已审核 Party 或既有资产候选，但不得因高置信度自动绑定；Party 和 Asset 引用必须由用户显式选择确认后写入。解析出的合同主体名称如未匹配到已审核 Party，只能提示用户先完成 Party 创建和审核后再选择，不得在解析确认动作中直接创建并写入主体；解析出的资产地址或坐落未匹配到既有资产时，只能提示用户先维护资产主档后再选择，不得直接创建并绑定新资产。

扫描件解析确认页中，OCR/AI 未识别但由用户手工补齐的目标对象字段，应显示“手工补齐”或“手工录入”类视觉来源标记；保存后只作为字段来源快照支持编辑或补录来源上下文查看，业务详情主视图不默认展示该标记。MVP 不为“纯手工录入”和“解析未识别后手工补齐”新增不同来源枚举，二者长期来源值统一为 `manual`，仅由 UI 按场景选择展示文案。确认页可主动列出少量建议补全的非必填经营关键字段，但不展开目标对象全部可选字段；合同建议字段限签订日期、付款周期、备注类关键经营字段，产权证建议字段限证载面积、期限、限制信息。建议补全字段属于数据质量提示，用户不填写时不阻断解析确认保存，空值按 `manual` 进入字段来源快照；保存后仍为空时，系统可在合同或产权证详情/编辑上下文展示补录完整性提示，不生成任务、待办或审批，也不作为保存门禁。该约束适用于 REQ-RNT-003、REQ-AST-005 和 REQ-DOC-001。

### 6.4 到期后新签

MVP 不提供“续签”业务能力。合同期满后如继续合作，按新合同补录流程重新创建合同关系和合同记录，历史合同保留扫描件和补录字段用于查询与审计。

## 7. 功能需求

### 7.1 资产域

| 编号 | 需求 | 验收标准 |
|---|---|---|
| REQ-AST-001 | 资产主数据统一管理 | 支持分页、筛选、排序、搜索、软删除、恢复、导入、模板校验 |
| REQ-AST-002 | 资产与项目、权属关系可追踪 | 单资产同一时点只有一个当前有效项目和主产权主体，关系变更可追溯 |
| REQ-AST-003 | 关键主数据支持两步确认与反审核 | 制单人提交（`draft → pending`）、确认（`pending → approved`）两步生命周期，**支持批量提交与批量审核**（导入资产统一落 `draft`，可批量提交转 `pending`、批量审核转 `approved`）；**确认仅按复核权限门控，不限制审核人 ≠ 提交人**——任何持复核权限者均可确认，包括提交人本人；审核状态可追踪，关键字段审核后受控（`approved`/`reversed` 下禁编辑），反审核后可重新提审。资产不走路由审批流，仅 `review_status` 字段上的轻量两步控制 |
| REQ-AST-004 | 资产详情口径清晰展示 | 展示资产基本信息、租赁情况、客户摘要，按四类合同关系汇总 |
| REQ-AST-005 | 资产产权证管理 | 资产详情内维护产权证，支持证照新增、编辑、附件、轻量在线预览、扫描件解析预填、证号唯一校验、已审核权利人 Party 关联、有效期/限制信息展示；产权证证号全局唯一且正式保存必填，同一本产权证覆盖多个资产时应在同一产权证记录上关联多个资产，不得以相同证号创建多条产权证；从资产 B 详情上传或录入已归属资产 A 的相同证号时，不创建新产权证，应提示证号已存在并展示既有产权证摘要，可在资产 B 当前详情页引导用户显式确认后追加资产关联，不强制跳转产权证详情页；系统不得因证号匹配自动绑定资产 B；若重复证号由本次扫描件上传触发，本次扫描件应作为既有产权证的附件候选，默认随追加资产关联一并保留，但必须由用户确认，用户可取消附件追加以避免重复附件；若既有产权证当前没有任何附件，则本次扫描件不得取消追加，取消时不能完成追加资产关联；产权证与资产为多对多平等关联，MVP 不区分主资产和附属资产；产权证必须至少关联一个既有资产，不允许保存为孤立证照记录；用户可追加或移除产权证资产关联，但不得删除最后一个资产关联；产权证统一使用“附件”承载证照事实底座，必须至少保留一份附件，附件上传仅接受 PDF、JPG/JPEG、PNG，单个文件大小上限为 20MB，超限时应提示压缩或拆分后重新上传；附件上传后不自动触发扫描件解析，上传附件和解析辅助补录是两个独立动作，用户需要解析时再手动触发；产权证解析入口只能选择当前产权证附件列表中的附件发起解析，不支持在解析入口重新上传新文件；需要解析新文件时，应先作为附件上传或追加，再由用户手动触发解析；同一附件重新解析时应生成新的临时解析结果，旧的未确认候选直接废弃，不做候选版本保留或对比；解析确认页不支持保存草稿或稍后继续确认，用户可取消解析，之后重新解析或手工补录；产权证解析确认成功后自动返回产权证详情或编辑页并展示保存成功提示，不保留确认结果页；已确认写入产权证主数据的字段不受重新解析影响；同一次操作允许多选上传多个附件，但每个文件独立校验类型和大小，不合规文件不得进入附件列表，合规文件可继续保留；PDF 附件支持内嵌预览，JPG/PNG 支持图片预览，预览跟随产权证查看权限，且不单独记录操作日志；下载是独立资料外流动作，下载按钮和下载接口必须校验产权证附件下载权限，不得仅凭产权证查看权限放行；MVP 不要求批注、旋转、裁剪、全文搜索或 OCR 原文高亮；预览失败时只提示“预览失败，可下载查看”，不阻断产权证保存、附件保留或扫描件解析；允许用户追加、替换、下载或删除附件，但删除最后一份附件应被阻止；附件下载应记录轻量操作日志，记录下载人、下载时间和附件，不要求填写下载原因，也不记录下载来源页面、入口、客户端 IP 或设备信息，不触发审批或告警；下载日志仅在系统操作日志/审计日志查询，不在产权证详情页默认展示；MVP 只支持单个附件下载，不提供多附件打包下载；系统操作日志可按产权证号筛选产权证附件下载或变更记录，附件文件名仅作为日志展示信息，不作为 MVP 筛选条件；替换附件时新附件取代旧附件，MVP 不保留被替换旧附件；删除附件不要求填写或记录删除原因；附件上传可按同名或相同文件哈希做疑似重复提示，疑似重复时只提示“疑似重复附件”，不展示具体命中依据，默认不追加，用户显式选择追加即视为确认，不要求二次确认弹窗，确认后仍可追加，不作为保存阻断；MVP 不要求附件版本管理、替换审批、附件差异追踪，也不新增附件备注字段、附件维护来源字段、附件总容量配额、多附件打包下载、批量解析、批量确认或复杂上传队列治理；附件追加、替换、删除或下载动作如需追溯由通用操作日志承载；其中追加、替换、删除日志记录附件 ID、文件名、动作类型、操作人和操作时间，不记录操作原因，不保留被替换或删除的旧文件内容，也不做附件差异记录；同一本产权证可关联多个资产，不限制为单资产证照；任一关联资产当前主产权主体未包含在产权证权利人 Party 列表中时，只对该资产在资产详情产权证区域、产权证详情/编辑页和项目风险摘要展示 `warning` 级数据质量风险，不阻断保存；正式保存硬门槛只包括证号全局唯一且非空、至少一个既有资产关联、至少一份附件、权利人引用已审核 Party（MVP 不含核验状态，`is_verified` 已删，见 ADR-0005）；证照信息不完整按 `warning` 级数据质量风险提示，不阻断资产维护、合同补录、台账生成或经营统计；产权证风险不进入全局搜索，不单独建立风险处置流程，也不允许手工关闭、忽略或标记已处理；风险由当前产权证数据实时派生，只能通过补齐证照信息或修正权利人/资产关联自然消除；证载面积、期限或限制信息为空时可在资产详情产权证区域和产权证详情/编辑页展示轻量补录完整性提示，不生成任务、待办或审批，不阻断产权证保存；解析结果必须人工确认后写入，解析失败不阻断手工维护，低置信字段必须逐项处理，处理方式只能是确认候选值、修正为手工值，或在非必填字段上显式选择暂不填写或留空；未处理的低置信字段不得直接提交确认；解析失败或低置信字段较多时不生成待办或任务，只在当前解析确认页和产权证编辑页提示，用户可手工补录或重新解析；非必填解析字段允许用户选择暂不填写或留空，空值按 `manual` 写入字段来源快照，必填字段仍必须补齐后才能确认保存；用户可在确认页补齐解析未识别出的目标对象字段，字段来源记为 `manual`，但不得新增不属于目标对象字段契约的临时字段；关键字段展示页码、文本片段或截图区域等轻量来源证据，保存时记录字段来源快照并在编辑或补录来源上下文按需查看，业务详情主视图不默认展示；解析字段与当前已保存字段冲突时不得自动覆盖，已有字段默认保留，解析候选仅作为差异提示，用户逐字段确认或修正后才写入；解析出的权利人和坐落可推荐候选 Party 或 Asset，但不得自动绑定，必须由用户显式选择确认；权利人未匹配到已审核 Party 时不得直接创建并写入产权证，坐落未匹配到既有资产时不得直接创建并关联新资产，也不得保存为无资产关联的产权证 |

| 分类 | 要求 |
|---|---|
| 安全 | PII 字段必须加密，状态变更请求必须防 CSRF，关键操作必须审计 |
| 权限 | 所有业务查询必须按主体绑定过滤，未授权对象不可见 |
| 性能 | 常规列表 P95 <= 800ms，统计和搜索 P95 <= 2s |
| 并发 | Asset 使用乐观锁（`version_id_col`），并发冲突返回明确错误；台账等高并发批量写路径由幂等保证（见下「幂等」行），不另加乐观锁。MVP 不再用「核心实体」这种无边界表述 |
| 幂等 | 批量台账更新、补偿任务、审批回调等关键写操作必须幂等 |
| 可维护性 | API 统一版本化，路由层和业务层分离 |
| 兼容性 | MVP 支持 Chrome 最新两个大版本和 Edge 最新版 |

## 9. 验收标准

MVP 放量前必须同时满足：

| 门槛 | 标准 |
|---|---|
| G1 | 资产页和项目页能清晰展示资产信息、四类合同关系租赁情况和客户摘要 |
| G2 | 合同关系能力可用，支持承租、代理、盖章扫描件解析预填、人工确认补录和台账维护 |
| G3 | 经营统计口径可用，支持总收入、自营租金、代理服务费、客户主体数、客户合同数 |

建议验收覆盖：

- 创建资产重名拦截。
- 面积不一致拦截。
- 资产已关联合同时删除拦截。
- 资产详情按四类合同关系展示租赁情况。
- 项目必须绑定运营管理方。
- 多绑定用户常规列表展示并集去重数据。
- 合同关系模式校验阻止承租和代理混用。
- 合同上传盖章扫描件后解析预填关键字段，人工确认补录租金或服务费条款后生成台账。
- 产权证上传扫描件后解析预填证号、权利人、坐落、面积、期限和限制信息，人工确认后写入资产详情内产权证。
- 产权证证号正式保存必填且全局唯一；重复证号应提示关联或维护已有产权证，不能创建第二条相同证号产权证；从另一个资产详情发现重复证号时，可在当前资产详情页展示既有产权证摘要并引导追加当前资产到既有产权证，但必须用户显式确认，不得自动绑定；本次上传扫描件作为附件候选默认一并追加，但用户可取消附件追加；若既有产权证当前没有附件，则不得取消本次扫描件追加。
- 同一本产权证关联多个资产时不区分主资产和附属资产；展示可按资产名称或编码排序，风险按每个关联资产独立判断。
- 产权证权利人与关联资产当前主产权主体不一致时，对对应资产生成 `warning` 级数据质量风险提示，只在资产详情产权证区域、产权证详情/编辑页和项目风险摘要展示，不阻断保存；该风险不能手工关闭、忽略或标记已处理，只能通过修正源数据自然消除。
- 保存合同补录时至少保留一份盖章扫描件；保存产权证时至少关联一个既有资产，且至少保留一份附件；产权证附件上传仅接受 PDF、JPG/JPEG、PNG，单个文件大小上限为 20MB；附件上传后不自动触发扫描件解析，上传附件和解析辅助补录是两个独立动作，用户需要解析时再手动触发；产权证解析入口只能选择当前产权证附件列表中的附件发起解析，不支持在解析入口重新上传新文件，需要解析新文件时应先作为附件上传或追加。产权证同一次操作可多选上传多个附件，但逐文件校验类型和大小，不合规文件不得进入附件列表，合规文件可继续保留；产权证附件支持轻量在线预览，PDF 可内嵌预览，JPG/PNG 可图片预览，预览跟随产权证查看权限，且不单独记录操作日志，不要求批注、旋转、裁剪、全文搜索或 OCR 原文高亮；下载按钮和下载接口必须校验产权证附件下载权限，不得仅凭产权证查看权限放行；预览失败只提示“预览失败，可下载查看”，不阻断产权证保存、附件保留或扫描件解析；产权证资产关联和附件都允许追加或删除，但不得删除到 0 个资产关联，也不得删除最后一份附件；附件下载记录轻量操作日志，记录下载人、下载时间和附件，不要求下载原因，也不记录下载来源页面、入口、客户端 IP 或设备信息，不触发审批或告警；下载日志仅在系统操作日志/审计日志查询，不在产权证详情页默认展示；MVP 只支持单个附件下载，不提供多附件打包下载；系统操作日志可按产权证号筛选产权证附件下载或变更记录，附件文件名仅作为日志展示信息，不作为 MVP 筛选条件；附件追加、替换、删除日志记录附件 ID、文件名、动作类型、操作人和操作时间，不记录操作原因，不保留被替换或删除的旧文件内容，也不做附件差异记录；附件替换时新附件取代旧附件，不保留被替换旧附件；删除附件不要求填写或记录删除原因；MVP 不要求附件版本管理、替换审批、差异追踪、附件备注字段、附件维护来源字段、附件总容量配额、多附件打包下载、批量解析、批量确认或复杂上传队列治理。产权证附件疑似重复时只提示，不阻断保存；用户显式选择追加即视为确认，不再二次确认。
- 产权证 MVP 不做核验状态（`is_verified` 已删，见 ADR-0005）；产权证数据质量风险只剩客观两类——证照信息不完整、权利人与关联资产当前主产权主体不一致，均不阻断资产维护、合同补录、台账生成或经营统计。
- 低置信字段必须高亮展示，并由用户逐项处理后才能随最终载荷保存；处理方式只能是确认候选值、修正为手工值，或在非必填字段上显式选择暂不填写或留空；未处理的低置信字段不得直接提交确认。
- 产权证解析失败或低置信字段较多时，不生成待办或任务，只在当前解析确认页和产权证编辑页提示；用户可手工补录或重新解析。
- 同一产权证附件重新解析时，旧的未确认解析候选直接废弃，不保留候选版本对比；已确认写入主数据的字段不受影响。
- 非必填解析字段允许用户选择暂不填写或留空，保存时按 `manual` 记录空值来源；必填字段仍必须补齐后才能确认保存。
- 解析确认页不支持保存草稿或稍后继续确认；用户可取消解析，之后重新解析或手工补录；产权证解析确认成功后自动返回产权证详情或编辑页并展示保存成功提示，不保留确认结果页。
- MVP 不提供“一键采用全部高置信无冲突字段”或批量采纳解析候选；所有解析候选都按字段逐项确认或修正。
- 解析字段与已保存字段冲突时不得自动覆盖，已有字段默认保留；解析候选以差异提示呈现，用户逐字段确认或修正后才写入。
- 关键解析字段在确认页展示页码、文本片段或截图区域等轻量来源证据，不要求全文标注编辑器；确认后不长期保存这些字段级来源证据。
- 系统可为解析出的主体、权利人、地址或坐落推荐已审核 Party 或既有资产候选，但用户未显式选择确认前不得写入引用。
- 解析会话确认、取消、失败或放弃后不作为长期记录保留；长期追溯依赖合同或产权证主数据、附件和字段来源快照，不记录解析工具、模型、供应商、置信度、确认时间、页码、文本片段或截图区域。
- 保存合同或产权证时可按字段区分手工录入、解析预填确认和解析预填修正；用户可在确认页补齐解析未识别出的目标对象字段，字段来源记为 `manual`，但不得新增不属于目标对象字段契约的临时字段；不要求展示复杂版本差异；业务详情主视图不默认展示字段来源，编辑或补录来源上下文可按需查看。
- 解析确认保存时，确认载荷中每个写入目标对象的字段都必须带有对应 `field_sources`；来源缺失应阻断确认保存。普通非解析编辑不要求前端提交字段来源，服务端可将缺失来源按手工录入默认补为 `manual`。
- OCR/AI 未识别但由用户在解析确认页手工补齐的目标对象字段，确认页应显示手工补齐或来源标记；保存后该标记仅通过字段来源快照在编辑或补录来源上下文按需查看，不默认进入业务详情主视图；MVP 不拆分 `manual` 来源枚举，不新增 `manual_after_ocr_miss` 或类似子类型。
- 解析确认页可主动列出少量 OCR/AI 未识别但建议补全的非必填经营关键字段：合同限签订日期、付款周期、备注类关键经营字段，产权证限证载面积、期限、限制信息；确认页不得展开目标对象全部可选字段，完整维护仍通过合同或产权证普通编辑页完成；建议补全字段不填写不阻断确认保存，空值按 `manual` 写入字段来源快照；保存后仍为空时，只在详情或编辑上下文展示补录完整性提示，不生成任务、待办或审批，不阻断后续保存。
- 扫描件解析出的主体或权利人未匹配已审核 Party 时，只提示创建/审核路径，不直接写入合同或产权证。
- 扫描件解析出的资产地址或坐落未匹配既有资产时，只提示资产主档维护路径，不直接创建或绑定新资产，也不得保存为无资产关联的产权证。
- 合同补录更正后旧台账按规则重算或作废；已收/部分已收条目不自动改写，留待人工处理。
- 客户双指标正确去重展示。
- 扫描件解析失败、超时或低置信度时可重试、人工修正或完全手工补录。
- 搜索结果不返回未授权对象。
- 合同到期与付款逾期通知只发给数据范围内可见该对象的用户；逾期通知按派生口径触发，不依赖人工翻态；通知无处理闭环，只有已读/未读。
- 产权证风险不进入全局搜索，不单独建立风险处置流程，不提供关闭、忽略或已处理状态。

## 10. vNext 候选能力

| 能力 | 说明 |
|---|---|
| 错误恢复模块正式化 | 将错误恢复从工程能力提升为正式产品能力 |
| 系统设置模块稳定化 | 将系统设置纳入稳定功能范围 |
| 集团汇总视图 | 支持集团总部汇总查看所有产权方和运营方数据 |
| 高级多角色冲突策略配置 | 支持更复杂、可配置的多角色冲突解释，不改变 MVP 显式拒绝优先语义 |
| 合同审批与状态流转 | 如未来需要控制合同生效、联审、反审核和制审分离，另行补齐合同审批基线 |
| 资产变更级审批 | 如未来需要对资产具体变更（出租、出售、调价）分别路由审批，重建审批流引擎并升级为变更级；MVP 资产只做 `review_status` 两步确认 |
| 可配置职责分离体系 | 提权审核与业务审核隔离、可配置互斥范围与冲突矩阵；**MVP 不做职责互斥**（资产确认只按复核权限门控，不限制审核人 ≠ 提交人），如将来需要由 vNext 引入可配置互斥体系 |
| 权属方管理 | 如需恢复旧独立 Ownership 管理模块，补齐与 Party 产权方角色的边界后再纳入正式基线 |
| 扫描件批量解析 | 如后续补录量证明必要，再设计批量上传、批量解析进度和批量任务治理；不得绕开单条人工确认规则 |
| 风险标签规则自动标注 | 从人工标注升级为规则自动加人工补充 |
