# 土地物业资产运营管理系统 PRD

## 1. 文档定位

本文档描述资产运营 v5 的产品目标、范围和验收边界。字段、状态机和统计口径以 [`docs/specs/domain-model.md`](specs/domain-model.md) 为准，API、权限和错误契约以 [`docs/specs/api-contract.md`](specs/api-contract.md) 为准，实现状态和证据以 [`docs/traceability/requirements-trace.md`](traceability/requirements-trace.md) 为准。

### 1.1 当前产品基线

2026-10-22，资产运营 v5 被确认为当前开发基线。可点击设计稿为 [`frontend/prototype/asset-ops-v5.html`](../frontend/prototype/asset-ops-v5.html)，业务与交互说明为 [`frontend/prototype/asset-ops-v5-handoff.md`](../frontend/prototype/asset-ops-v5-handoff.md)，边界裁决见 [ADR-0028](architecture/ADR-0028-asset-operations-v5-workbench-boundary.md)。

v5 取代此前 v4.0 多岗位、全经营链方案。旧方案只用于历史追溯和迁移盘点，不再定义当前产品范围。S0 规格已收口，当前在 `codex/asset-ops-v5-s0` 分支实施 V1 资产单元与合同链；实现状态只以需求追踪矩阵为准。

## 2. 背景与问题

资产管理岗目前依赖分散的物业、合同、租金、对账和档案台账完成月度工作，存在四类直接问题：

1. 上游合同、物业单元和终端合同之间缺少稳定关联，数量和金额容易在不同表中不一致。
2. 承租租金、终端租金、委托管理费和押金缺少统一的到期、部分完成、撤销与跨月结转口径。
3. 每月出租率报送依赖人工汇总，考核范围、已报快照和当前台账容易互相覆盖。
4. 扫描件分散，无法直接回答每个物业或合同“应有几份、已有几份、缺什么”。

系统目标不是替代 OA、合同审批系统、银行或财务总账，而是在合同签订之后为资产管理岗建立唯一、可追溯的运营事实和月度工作入口。

## 3. 产品目标

### 3.1 MVP 一票否决目标

| 目标 | 验收含义 |
|---|---|
| 台账数字一致 | 本月、物业、合同、台账、报送和档案均从同一事实链推导，同一指标在不同页面不得出现不同值 |
| 历史不可回写 | 合同续签、单元拆合、付款撤销、考核范围调整和报送撤回均追加事实，不能静默覆盖历史月份 |
| 报送可复现 | 每个已报月份都能还原当时的资产单元、考核范围版本、宗数、面积和出租状态 |
| 资金登记可信 | 付款、到账、产权方到账报告、押金收退和撤销均可追溯到金额、日期、凭证、操作人和原因 |
| 风险不隐藏 | 上游缺失、租期越界、合同到期未处理、档案缺漏、部分付款和无权限必须明确呈现 |
| 批量变更可控 | 导入和批量更新先校验差异，错误清零后原子提交，并可在限定窗口内整批撤销 |

### 3.2 上线后三个月成功指标

| 指标 | 目标值 | 认定规则 |
|---|---|---|
| 月度出租率报送按时完成率 | 100% | 每月 1 日完成上月报送，撤回后重新提交仍保留原快照和原因 |
| 核心台账口径差异 | 0 个/月 | 本月、物业、合同、台账、报送抽查同一事实，宗数、面积、金额和状态一致 |
| 付款和到账可追溯率 | 100% | 每笔登记可反查对应义务、日期、凭证或无凭证说明，以及撤销链 |
| 档案缺漏可解释率 | 100% | 缺漏矩阵中的每个“应有”数量都能下钻到具体物业或合同 |
| 批量导入部分写入事故 | 0 次 | 任一错误导致整批不写入；撤销后不残留半批数据 |

## 4. MVP 范围

### 4.1 In Scope

| 范围 | 能力 |
|---|---|
| 本月工作台 | 汇总有截止日的支付、收取、管理费对账和出租率报送；单列无固定截止日的到期、档案、押金和新增单元事项 |
| 物业台账 | 维护资产单元物理信息、项目归属标签、产权方、经营性质、空置原因、预计起租、合同链和产权证关系 |
| 已签合同 | 录入上游承租合同、委托管理协议和终端合同；维护覆盖单元、租期、租金计划、押金、扫描件、续签链、终止与退出 |
| 租金台账 | 生成承租租金应付和终端租金应收，支持部分登记、跨月欠款、凭证和有原因撤销 |
| 委托管理费 | 登记产权方实际收到的终端租金，按协议比例试算，生成每产权方每月一张对账单并以双方盖章确认 |
| 押金 | 展示应收未收、应付未付、应退未退和应收回四类待处理事项，保留约定、收取方、持有余额和处理记录 |
| 出租率报送 | 维护年度考核范围版本，生成月度草稿、门槛核对、变动说明、报送快照、撤回和差异提示 |
| 档案 | 将产权证、上游合同、补充协议、终端合同、交接书和对账单挂到业务对象，并按“已有/应有”集中展示 |
| 数据导入 | 支持新增数据与更新已有数据两种模式，提供逐行校验、差异预览、原子提交、批次记录和限定窗口撤销 |
| 平台基础 | 登录、组织、主体、数据范围、角色授予边界、操作日志和稳定 403 继续作为共享基础能力 |

### 4.2 Out of Scope

| 能力 | 边界 |
|---|---|
| 招商意向和条件审议 | 不维护意向、报价、底价、竞争洽谈或空间锁定 |
| 合同审批与生效门 | 合同在外部系统签订；本系统不建设 BPM、授权冻结、底价例外或生效检查 |
| 银行流水认领 | 不导入银行原始行，不做匹配、候选、复核分配或未分配预收 |
| 发票与财务总账 | 不维护税票、开票分摊、会计凭证、支付指令或总账余额 |
| 催收和法务案件 | 不建设欠费账户、催收案件、法务升级或自动外发消息 |
| 产权方协同门户 | 不为产权方、租户或外部人员提供账号与工作台 |
| 领导驾驶舱 | 不提供领导专用只读视角、利润分析或跨岗位驾驶舱 |
| 多人任务分派 | 不按人员分配待办，不建设岗位内任务派发或绩效系统 |
| 物业维修作业 | 不建设巡检、维修工单、验收、改造或消防流程 |

## 5. 角色、权限与数据范围

### 5.1 业务角色

MVP 只有“资产管理岗”一个业务角色。该角色可以在授权主体和项目范围内读取、维护、报送、导入和归档资产运营数据。页面不提供角色切换、领导模式或按人分派。

系统管理员、权限管理员和服务账号属于平台治理身份，不是资产运营业务角色：

- `admin` / `system_admin` 管理平台并按既有规则获得业务访问。
- `perm_admin` 只能配置权限，不得读取业务数据或把业务角色授予自己。
- 普通资产管理用户仍受 Organization、Party 和有效数据范围约束；范围缺失或失效必须失败关闭并返回明确 403。

### 5.2 能力边界

业务能力至少拆为读取、维护、报送、档案和导入五类权限。前端导航、页面路由、深链和后端端点使用同一能力声明；隐藏导航不能替代后端鉴权。

## 6. 核心业务口径

### 6.1 两种经营模式

| 模式 | 关系 | 本系统记录 |
|---|---|---|
| 承租模式 | 产权方 → 上游承租合同 → 本公司 → 终端转租合同 → 终端租户 | 上游应付租金、终端应收租金、双方押金和合同档案 |
| 委托管理模式 | 产权方 → 委托管理协议 → 本公司受托；产权方 → 终端直签合同 → 终端租户 | 产权方实际到账报告、直签押金的产权方报告、委托管理费对账和合同档案 |

全系统统一使用“委托管理协议”“委托管理费”，不使用“代理协议”“代理费”。

### 6.2 事实链与投影

资产单元是最小可租、逐宗计数的物业边界。每份终端合同覆盖一个或多个资产单元；合并出租不合并宗数。上游合同覆盖其管理范围内的资产单元，项目只是管理归属标签。

本月任务、三类台账、出租状态、到期提醒、档案缺漏、报送说明和完成率全部由合同、资产单元及追加记录推导，不提供独立修改入口。

### 6.3 合同与关系风险

- 上游合同和终端合同均从“已经签署”开始录入，可通过前驱合同建立续签链。
- 终端合同允许暂时选择“上游尚未录入”；单元有有效终端合同时仍计为已出租，同时显示上游缺失风险。
- 终端转租期限超出上游承租期限时明确标红，但不阻止登记已经存在的合同。
- 上游合同到期后未续签也未退出时，资产单元继续计入在管，相关终端合同显示“暂无上游依据”。
- 上游退出前必须处理名下仍有效的终端合同；终端合同终止后保留只读历史。

### 6.4 资产单元和出租状态

- 资产单元拆分或合并按生效日追加边界变化；原单元在前一日停止计宗，新单元从生效日起计宗。
- 合并只能发生在相同且非空的有效上游合同集合内，拆分和合并的面积合计必须守恒。
- 出租状态以统计月最后一天是否存在有效终端合同派生，不允许手工修改。
- 空置原因和预计起租只是经营备注，不影响出租状态和宗数。
- 产权证与资产单元是多对多关系；证照存在不等于已出租。

### 6.5 租金、押金与管理费

- 承租租金按合同结构化条款生成义务；月付在约定月出应付，季付只在季初月出应付（从起租月起每 3 个月），递增按阶段复利叠加。
- 终端租金未完成的往月义务持续结转，不随月份切换消失。
- 付款和到账允许部分登记；少于应付/应收时显示剩余金额。
- 撤销付款、到账、终止和退出必须填写原因并保留原记录。
- 委托管理费基数为产权方实际收到的终端租金；月末仍未收到的户顺延后续期间，不阻塞当月已具备条件的对账。
- 已盖章对账月份的基数和金额锁定，合同后来变化不回写。
- 押金按合同跟踪约定金额与实际持有：转租押金由本公司向租户收取，直签押金由产权方收取（本系统只登记产权方报告），承租合同押金由本公司付给产权方；委托管理协议不约定保证金。待处理分应收未收、应付未付、应退未退和应收回四类；续签时押金整体转入后继合同；合同终止或到期后，转租押金可按到期先后抵扣欠租，终止时默认自动抵扣截至当月的欠租。押金中不退还的部分（赔偿、违约金或产权方扣留）登记为押金扣除，原因必填。
- 提前退租时可登记补收已享免租优惠的应收（金额与依据人工填写），参与押金抵扣。
- 租金阶段在合同录入和续签时一并核对录入；确认后可以更正：往月已有的阶段不能改，往月没有阶段的日期可以补录，更正只影响当月起和补录月份尚未登记的义务，其余历史月份不回写；合同级付款周期和付款日确认后只读，付款方式以租金阶段为准。

### 6.6 考核范围与月度报送

- 考核范围和月度报送按本公司的运营主体（Party）独立维护；每个运营主体有自己的年度范围版本和月度报送链，不以当前用户或临时可见资产集合代替报送单位。
- 考核范围按年度、资产单元和版本维护；默认纳入年初已在管的存量经营性物业，不纳入必须填写原因。存量补录按开始在管日期认定，不按系统登记日期认定。
- 年中新增接管的资产单元在人工确认前不进入当年报送分母；拆分或合并的全部来源已纳入时，结果单元自动继承纳入，来源决定不一致时须人工确认。
- 新保存的范围可以用于尚未提交的上月报送，已提交快照继续引用原版本，不因范围变更回写。
- 报送草稿始终从当前事实实时计算；改变分母的必处理项未清零或有变动但未填写说明时不得提交。
- 提交后锁定月度快照及当时考核范围版本；后续台账变化只显示差异，不改写快照。
- 撤回必须填写原因；原快照和变更记录保留。
- 每月 1 日生成上月报送任务，上月未完成事项继续显示拖延天数。

### 6.7 档案和导入

- 档案文件必须挂到产权证、资产单元、合同、交接或对账对象，档案页本身不另建第二份文件事实。
- “应有份数”由业务对象和期间推导，缺漏可以下钻到具体对象。
- 新增导入按稳定编号拒绝重复；更新导入只更新明确填写的字段，空白不覆盖现值，派生字段始终忽略。
- 导入在确认前展示“现值 → 新值 → 影响”；任一错误阻止整批写入，提醒不阻止。
- 批次撤销追加反向记录，已报送月份不受影响。

## 7. 功能需求

| 编号 | 需求 | 验收标准 |

| REQ-RPT-002 | 月度出租率报送 | 支持草稿、门槛、变动说明、明细、快照、撤回、差异和历史月份读取 |
| REQ-ARC-001 | 业务档案矩阵 | 按产权证、合同、补充协议、交接书和对账单展示已有/应有，支持多文件配对与缺漏下钻 |
| REQ-IMP-001 | 批量新增和更新 | 支持模板、逐行校验、差异选择、影响预览、幂等原子提交、批次记录和限定窗口撤销 |
| REQ-AUTH-001 | 统一认证与鉴权 | 业务路由和写操作必须鉴权，业务角色和平台管理角色边界清楚 |
| REQ-AUTH-002 | 数据范围失败关闭 | 业务查询、统计、任务和导出统一应用有效 Party 范围；无范围或失效范围返回稳定 403 |
| REQ-SYS-001 | 平台用户与组织 | 保留用户、角色、组织、Party 和审计基础能力，不把系统管理入口混入业务工作台 |

## 8. 非功能需求

- 所有公开 API 使用 `/api/v1/*`，写请求支持幂等和乐观并发冲突。
- 列表和详情分别支持加载、空、无权限和出错状态；刷新失败保留旧数据并显示错误编号。
- 目标桌面宽度为 1280px 及以上；200% 缩放时内容和操作仍可达。台账矩阵可以在自身容器内横向滚动。
- 键盘可以完成所有操作；控件有可访问名称、可见焦点，减少动态效果偏好得到尊重。
- 金额使用十进制定点语义，日期按业务时区解释，动态数值使用等宽数字。
- 关键写操作记录操作者、时间、前后值、原因、幂等键和关联版本。
- 导出、快照和批次处理不得通过同步长请求阻塞普通查询；失败应可重试且不重复写入。

## 9. 验收门槛

| 门槛 | 标准 |
|---|---|
| G1 | 上游合同、资产单元、终端合同的覆盖关系唯一且可追溯，派生页面之间数字一致 |
| G2 | 部分付款、到账、押金和撤销保持原事实，不通过覆盖累计值制造结清 |
| G3 | 年度考核范围版本和月度报送快照可重放，历史月份不被当前台账改写 |
| G4 | 资产单元拆合前后宗数和面积在生效日边界守恒，历史统计不回写 |
| G5 | 导入错误时零写入，成功批次可追踪并在规则允许时整批撤销 |
| G6 | 无权限、上游缺失、租期越界、到期未处理和档案缺漏均明确可见，不被空态或默认值掩盖 |
| G7 | 1280px、200% 缩放、键盘和减少动态效果场景通过界面验收 |

至少覆盖以下边界场景：

1. 一份终端合同覆盖三个资产单元，出租率增加三宗而非一宗。
2. 终端合同有效但上游尚未录入，仍计出租且所有相关页面显示同一风险。
3. 转租结束日晚于上游结束日，保存成功但风险始终可下钻。
4. 上游到期后仍有有效终端合同，退出被阻止且本月页持续提醒。
5. 资产单元在月中拆分，月末按新单元计宗，拆分前月份保持原值。
6. 一笔租金分两次登记后结清，再撤销第二笔，状态恢复为部分完成。
7. 已盖章管理费对账后修改合同比例，已确认月份金额不变化。
8. 已报送月份之后调整考核范围，新版本只影响后续月份。
9. 更新导入包含不存在的编号和派生字段，错误行阻止整批写入且派生列不被采用。
10. 数据范围 403、真实空列表和服务异常分别显示三种不同状态。

## 10. vNext 候选能力

- 多业务岗位和岗位内任务分派。
- 产权方或租户协同门户。
- 银行流水导入、认领与财务复核。
- 发票、财务总账、催收和法务案件。
- 物业巡检、维修、改造和验收。
- 领导经营分析、利润和预算。

候选能力只有在重新进入 PRD、领域模型、API 契约和验收计划后才能实施，不得以隐藏入口或预留字段提前进入 MVP。

## 11. 变更规则

- 产品范围变化修改本文档。
- 字段、状态机和统计口径变化修改 `docs/specs/domain-model.md`。
- API、权限、幂等和错误变化修改 `docs/specs/api-contract.md`。
- 实现状态和证据只修改 `docs/traceability/requirements-trace.md`。
- 设计稿不得自行创造业务口径；与 SSOT 冲突时先修订 SSOT，再更新设计稿。
