# 土地物业资产运营管理系统 PRD

## 1. 文档定位

本文档描述土地物业资产运营管理系统的产品目标态，是**产品、研发与验收**的产品需求基线（工程口径）。业务与设计在评审环节参与，但日常以派生摘要 / 视图为入口，不直接消费本文档的字段级口径。

本文档只回答“产品要做什么、为什么做、做到什么算完成”。字段、状态机、API 契约、代码实现证据、历史决策过程分别由其他文档承载。

|---|---|
| `docs/specs/domain-model.md` | 业务对象、字段、状态、枚举、统计口径 |
| `docs/specs/api-contract.md` | API、权限和请求契约 |
| `docs/traceability/requirements-trace.md` | REQ 到实现追踪信息的映射 |

## 2. 背景与问题

土地/物业资产运营当前存在资产台账分散、合同链路割裂、证照与主体信息分散、统计口径不统一等问题。现实经营同时包含承租模式与代理模式，跨产权方、运营方、终端客户的业务关系复杂，依赖人工台账和线下口径容易造成漏记、重复统计和权限风险。

系统目标是建设统一资产运营平台，以项目为普通用户的主工作对象，覆盖项目、资产、合同关系、合同、台账、客户、分析和权限，支撑运营管理闭环。

## 3. 产品目标

### 3.1 MVP 一票否决目标

| 目标 | 验收含义 |
|---|---|
| 资产清晰可见 | 资产页和项目页可展示资产基本信息、租赁情况、客户摘要 |
| 项目合同关系可用 | 承租模式与代理模式都可在项目下建模，且单条合同关系内模式不混用 |
| 合同补录和台账可追踪 | 盖章扫描件上传、必要经营字段补录、台账生成和更正均有留痕 |
| 经营统计口径可用 | 支持总收入、自营租金收入、代理服务费收入、客户双指标 |

### 3.2 上线后三个月成功指标

| 指标 | 目标值 | 认定规则 |
|---|---|---|
| 关键报表口径一致性问题 | <= 2 个/月 | 口径类缺陷以 issue 标签（`口径问题`）登记，按「确认为真实口径不一致的缺陷数」逐月计数，由产品负责人月度复盘认定；纯人工流程，不建系统功能或报表 |
| 核心经营链路真实可用 | 上线后首月达成 | 真实业务数据可端到端完成「扫描件上传 → 人工确认补录 → 台账生成 → 实收登记」核心链路（**二元达成**，不设比率 / 数量阈值以免凑数）；由产品负责人按真实使用抽验认定，不新建埋点系统。区别于 §3.1/§9 的**放量前**验收门槛——本指标确认**上线后真实生产数据**确有走通 |

> 原「资产台账完整率 >= 98%」与「核心流程平均处理时长下降 >= 40%」已删除：前者无口径定义，与已删的台账覆盖率同构（数据完整性由导入模板校验、资产两步确认、补录完整性提示机制保障，不靠事后指标）；后者无线下基线，不可证伪。MVP 的核心成功标准是 §3.1 一票否决目标与 §9 验收门槛。

## 5. 角色、权限与数据范围

系统采用角色、绑定、视图三维正交模型。

| 维度 | 解决的问题 | 规则 |
|---|---|---|
| 角色 | 用户能做什么操作 | 基于 RBAC 与 ABAC 控制按钮和接口级动作 |
| 绑定 | 用户能看哪批数据 | 基于用户绑定的产权方或运营方主体自动过滤 |
| 视图 | 同一数据用什么经营口径解读 | 仅分析和大屏使用 owner / manager 口径 |

核心规则：

- 用户权限 = 角色可执行动作与主体绑定数据范围的交集。
- 多角色权限默认取允许权限并集；如命中显式拒绝授权或拒绝数据策略，则拒绝优先。
- 权限管理员（`perm_admin`）只可管理用户、角色、权限配置、字典与审计，不可查看业务数据。该隔离是**强约束而非默认**：`perm_admin` 不得授予任何带业务数据范围的角色（业务角色），含授予自己；业务角色只能由 `admin`/`system_admin` 授予。授予前按角色业务数据能力分类校验，违规授予应被拒绝（见 ADR-0009）。此为静态角色授予边界，不是职责互斥矩阵，与「MVP 不做职责互斥」不冲突。
- 多绑定用户在常规列表中展示数据并集，并按业务实体主键去重。
- 分析和大屏不能混合产权方口径与运营方口径，必须按视图口径展示。
- 管理员和审计类用户可按授权查看全量数据。

## 6. 核心业务口径

### 6.1 客户定义

客户不是固定身份，而是合同对方主体。同一主体可在不同合同中扮演不同角色。

客户列表以主体为唯一行（按 Party live 去重），显示**当前主档名**并通过角色标签展示其在合同中的角色。历史合同详情则显示**签署时主体名称快照**（Contract `lessor_name_snapshot` / `lessee_name_snapshot`，定稿时固化、不因主档后续改名而追溯覆盖，见 ADR-0020）。Party「去重」指**建档时查重提示**（防重复建档），MVP **不做主体合并**——合并会回溯改写历史客户主体数/合同数口径，撞 §3.2，归 vNext（见 ADR-0020）。

### 6.2 经营模式

系统支持两种经营模式：

| 模式 | 结构 | 收入口径 |
|---|---|---|
| 承租模式 | 运营方从产权方承租，再向终端客户转租 | 自营租金收入 |
| 代理模式 | 产权方与终端客户直租，运营方提供代理管理 | 代理服务费收入 |

单条合同关系只能对应一种经营模式，不允许在同一合同关系内混用承租和代理。一个项目可以同时承载承租模式和代理模式，但展示和统计必须按模式分区。

合同关系**锁单项目**（承租/代理一律如此），其覆盖资产同属该项目。代理模式的**委托协议**（产权方↔运营方）可覆盖多个项目（**直租/上游/下游恒单项目**），但**跨项目落在盖章扫描件层**：同一份委托协议扫描件只上传一次，在覆盖的每个项目下各建一条合同关系/合同记录共享引用该扫描件，不创建跨项目的合同关系、不让合同组跨项目；每条租金/服务费台账仍落唯一项目（见 ADR-0012、ADR-0011）。

### 6.3 合同关系分类

| 分类 | 所属模式 | 含义 |
|---|---|---|
| 上游 | 承租模式 | 产权方与运营方之间的内部入约合同 |
| 下游 | 承租模式 | 运营方与终端客户之间的对外出约合同 |
| 委托 | 代理模式 | 产权方与运营方之间的委托管理协议 |
| 直租 | 代理模式 | 产权方与终端客户之间的对外出约合同 |

上下游/委托/直租仅是**收入与成本的方向标记**：下游/直租租金计入收入，上游租金计入成本，代理直租派生服务费收入——全部按每份合同的分类计算，不做合同对合同的逐对配对，也不做"主合同覆盖"判定。盈亏沿"合同 → 资产 → 项目"归属链汇总，当前成本/当前收益只在项目级（及合同关系级）呈现，不分摊到资产级。

MVP 全部合同按实际资料到达顺序补录、补录即生效（不做提审 / 审核 / 反审核，见 §4.2、ADR-0013），每份合同必须保留至少一份盖章扫描件作为事实底座。扫描件解析辅助补录、字段来源与附件管理遵循 §6.5。

### 6.4 到期后新签

MVP 不提供“续签”业务能力。合同期满后如继续合作，按新合同补录流程重新创建合同关系和合同记录，历史合同保留扫描件和补录字段用于查询与审计。

### 6.5 扫描件解析与附件通用规则

合同与产权证的扫描件解析辅助补录、附件管理遵循同一套产品规则（字段级机制、枚举与阈值见 `docs/specs/domain-model.md` §2「字段来源」「扫描件解析确认」与 §4.20~§4.23，本节只述产品意图）：

- **扫描件是事实底座**：合同补录必须保留至少一份盖章扫描件，产权证必须保留至少一份附件，删到最后一份被阻止。
- **解析只辅助、人工定夺**：OCR/AI 预填字段必须由用户逐项确认或修正后才写入；低置信字段必须逐项处理（确认候选值、修正为手工值，或非必填字段显式留空），不得静默落库；解析失败、超时或低置信不阻断完全手工补录。
- **不自动绑定、不自动覆盖**：解析出的主体 / 权利人 / 资产仅作候选推荐，必须用户显式选择已审核 Party 或既有资产后才写入；与已保存字段冲突时默认保留旧值、仅作差异提示，不自动覆盖。
- **不在确认动作里造主数据**：未匹配已审核 Party 只提示先创建并审核，未匹配既有资产只提示先维护资产主档，确认动作内不直接创建 Party 或 Asset，产权证不得保存为无资产关联的孤立证照。
- **解析会话即用即弃**：仅临时工作区，不存草稿、不可稍后继续，确认 / 取消 / 失败后不留档；长期事实以主数据、附件和字段来源快照为准，不记解析工具、模型、置信度、页码或截图等元信息。
- **建议补全不阻断**：确认页可列少量建议补全的非必填经营关键字段（合同限签订日期、付款周期、备注类；产权证限证载面积、期限、限制信息），不填不阻断保存，仅形成补录完整性提示。
- **附件能力轻量**：附件支持轻量在线预览（跟随查看权限、不单独记日志）；下载是独立资料外流动作，校验独立下载权限并记轻量下载日志；同名或哈希疑似重复只提示、不阻断。MVP 不做批量解析、批量确认、附件版本管理或打包下载。
- **来源可追溯不喧宾夺主**：保存时记字段来源快照（手工录入 / 解析确认 / 解析修正），仅在编辑或补录来源上下文按需查看，业务详情主视图不默认展示。

该规则适用于 REQ-AST-005、REQ-RNT-003 与 REQ-DOC-001。

## 7. 功能需求

### 7.1 资产域

| 编号 | 需求 | 验收标准 |
|---|---|---|
| REQ-AST-001 | 资产主数据统一管理 | 支持分页、筛选、排序、搜索、软删除、恢复、导入、模板校验 |
| REQ-AST-002 | 资产与项目、权属关系可追踪 | 单资产同一时点只有一个当前有效项目和主产权主体，关系变更可追溯。**主产权主体（`owner_party_id`）是资产内在权属事实，独立必填，挂资产本身、不随项目变**；**运营方（`manager_party_id`）随项目派生**——= 资产当前有效项目的运营方，资产挪项目则运营方随之改变，未归入项目时无运营方，运营方权威轴唯一在 Project（见 ADR-0010） |
| REQ-AST-003 | 关键主数据支持两步确认与反审核 | 制单人提交（`draft → pending`）、确认（`pending → approved`）两步生命周期，**支持批量提交与批量审核**（导入资产统一落 `draft`，可批量提交转 `pending`、批量审核转 `approved`）；**确认仅按复核权限门控，不限制审核人 ≠ 提交人**——任何持复核权限者均可确认，包括提交人本人；审核状态可追踪，关键字段审核后受控（`approved`/`reversed` 下禁编辑），反审核后可重新提审。资产不走路由审批流，仅 `review_status` 字段上的轻量两步控制 |
| REQ-AST-004 | 资产详情口径清晰展示 | 展示资产基本信息、租赁情况、客户摘要，按四类合同关系汇总 |
| REQ-AST-005 | 资产产权证管理 | 资产详情内维护产权证：证照新增、编辑、附件、轻量在线预览、扫描件解析预填、已审核权利人 Party 关联、有效期与限制信息展示。**正式保存 5 项硬门槛**：证号全局唯一且非空、至少一个既有资产关联、至少一份附件、权利人引用已审核 Party、坐落/地址非空（不动产权/房屋/土地证类型必填，其他证照类型按证号；2026-06-18 grill 扩 ADR-0005 原四项为五项；MVP 不含核验状态，`is_verified` 已删，见 ADR-0005）。同一本产权证可关联多个资产（多对多平等、不分主/附属），证号重复时维护既有产权证的资产关联、不新建第二条。证照信息（证载面积/期限/限制）缺失，或权利人与关联资产当前主产权主体不一致，只派生 `warning` 级数据质量风险，不阻断资产维护、合同补录、台账生成或经营统计，且实时派生不可手工关闭、不进全局搜索（见 §7.5）。解析辅助补录与附件管理遵循 §6.5；字段级契约见 `docs/specs/domain-model.md` §4.20（产权证）、§4.21（权利人关系）、§4.22（附件）、§2（字段来源） |

### 7.2 项目与主体关系域

| 编号 | 需求 | 验收标准 |
|---|---|---|

### 7.3 租赁与合同关系域

| 编号 | 需求 | 验收标准 |
|---|---|---|
| REQ-RNT-001 | 合同关系作为用户可见业务对象 | 合同关系归属项目，承载一笔经营关系，包含模式、主体、资产、合同、结算和风险信息；**合同关系锁单项目**（覆盖资产同属该项目，承租/代理一律如此），代理委托协议跨多项目时靠共享盖章扫描件、各项目各建一条合同关系，不让合同组跨项目（直租恒单项目，见 ADR-0012） |
| REQ-RNT-002 | 承租模式与代理模式并行支持 | 两种经营模式都可建模，同条合同关系不混用，同一项目下按模式分区展示 |
| REQ-RNT-003 | 合同盖章扫描件辅助补录 | 全部合同必须上传并保留至少一份盖章扫描件作为事实底座；系统解析合同编号、主体、资产、期间、金额、租金或服务费条款等关键字段并预填补录表单，用户人工确认或修正后写入并关联所属合同关系。解析确认、附件管理、字段来源、候选不自动绑定、建议补全（限签订日期、付款周期、备注类关键经营字段）等通用规则遵循 §6.5；字段级契约见 `docs/specs/domain-model.md` §2（字段来源、扫描件解析确认）、§4.22（附件）、§4.23（解析会话）|
| REQ-RNT-005 | 合同更正与作废留痕 | 补录错误可更正或作废并记录操作痕迹；已生成台账按**重算或作废**处理——重算只调整未收（`unpaid`）条目，**已收/部分已收（`paid`/`partial`）条目系统不自动改写或作废，自动跳过**；`voided` 作废由系统在重算或更正流程写入。被跳过的已收条目以两条机制提醒人工对账：(1) 重算结果当场在前端列出本次跳过的条目（条目、原因），用户即时可见；(2) **持久派生风险**——`paid`/`partial` 条目的 `amount_due` 或 `due_date` 与当前合同条款重算目标值不一致时，派生「已收台账与当前合同条款不一致」风险（`risk_type=ledger_stale_after_correction`），在合同关系与项目风险摘要展示，由数据实时派生、人工对账修正后自然消除，不设手工标记位、不能手工关闭（口径同逾期与产权证 `warning` 风险，见 ADR-0008）。MVP **无红字冲销**机制（属财务总账，见 §4.2），已收条目如需更正由人工在台账上处理 |
| REQ-RNT-006 | 台账自动化 | 按补录合同和租金/服务费条款生成台账，支持查询、实收登记、导出、补偿任务（扫描补齐缺失台账，幂等）和服务费台账；**台账实收登记**：按条目只登记 `paid_amount`，作为收缴率与实收统计的事实来源，`unpaid`/`partial`/`paid` 由 `paid_amount` 对 `amount_due` 派生，不允许人工翻收款状态；「逾期」不是登记状态，而是派生口径——`due_date` 已过且未收清（`paid_amount < amount_due`，状态非 `voided`）即逾期，统计、风险、筛选与通知全系统统一按此派生，不依赖人工翻状态（见 ADR-0007/0019）；MVP 只在台账条目上记一个实收总额，**不做分期收款流水、不记逐次收款日期明细**，也不对接真实资金通道（与 §4.2「支付结算」区分）；**台账是账本（历史记录）不是实时情况列表**——条目在生成时固化所属项目/产权方/运营方/资产归属，项目与产权方维度的历史和分析口径按固化归属聚合，资产或合同组 re-org 到别的项目不回写、不改写历史财务口径（见 ADR-0011） |

## 9. 验收标准

MVP 放量前必须同时满足：

| 门槛 | 标准 |
|---|---|
| G1 | 资产页和项目页能清晰展示资产信息、四类合同关系租赁情况和客户摘要 |
| G2 | 合同关系能力可用，支持承租、代理、盖章扫描件解析预填、人工确认补录和台账维护 |
| G3 | 经营统计口径可用，支持总收入、自营租金、代理服务费、客户主体数、客户合同数 |

建议验收覆盖：

- 创建资产重名拦截。
- 面积不一致拦截。
- 资产已关联合同时删除拦截。
- 资产详情按四类合同关系展示租赁情况。
- 项目必须绑定运营管理方。
- 多绑定用户常规列表展示并集去重数据。
- 合同关系模式校验阻止承租和代理混用。
- 合同上传盖章扫描件后解析预填关键字段，人工确认补录租金或服务费条款后生成台账。
- 产权证上传扫描件后解析预填证号、权利人、坐落、面积、期限和限制信息，人工确认后写入资产详情内产权证。
- 产权证证号正式保存必填且全局唯一；重复证号提示维护既有产权证、经用户显式确认后追加资产关联，不自动绑定（见 REQ-AST-005、§6.5）。
- 同一本产权证关联多个资产时不区分主资产和附属资产；展示可按资产名称或编码排序，风险按每个关联资产独立判断。
- 产权证权利人与关联资产当前主产权主体不一致时，对对应资产生成 `warning` 级数据质量风险提示，只在资产详情产权证区域、产权证详情/编辑页和项目风险摘要展示，不阻断保存；该风险不能手工关闭、忽略或标记已处理，只能通过修正源数据自然消除。
- 保存合同补录至少保留一份盖章扫描件；保存产权证满足 5 项硬门槛（证号唯一非空、≥1 既有资产、≥1 附件、权利人已审核 Party、坐落/地址非空）；附件类型/大小、上传不自动解析、轻量预览、下载独立权限、资产与附件 ≥1 下限、疑似重复只提示等行为见 §6.5、domain-model §4.22。
- 产权证 MVP 不做核验状态（`is_verified` 已删，见 ADR-0005）；产权证数据质量风险只剩客观两类——证照信息不完整、权利人与关联资产当前主产权主体不一致，均不阻断资产维护、合同补录、台账生成或经营统计。
- 扫描件解析确认全流程符合 §6.5 与 domain-model §2/§4.23：低置信字段逐项处理后才可保存、来源缺失阻断确认、候选不自动绑定或覆盖、解析会话不留档、失败/超时/低置信可重试或完全手工补录、未匹配已审核 Party 或既有资产只提示不在确认动作中创建、确认后不长期保存页码/片段等来源证据。
- 合同补录更正后旧台账按规则重算或作废；已收/部分已收条目不自动改写，留待人工处理。
- 客户双指标正确去重展示。
- 多绑定用户以 `scope_mode=all` 访问任一暴露客户双指标的端点时，客户双指标不在混合视图下计算：综合分析端点硬拒绝并要求选视图；项目分析端点靶向抑制客户双指标（置空 + 标记），其余分析摘要照常返回。
- 搜索结果不返回未授权对象。
- 权限管理员（`perm_admin`）尝试给任意用户（含自己）授予业务角色被拒绝；业务角色授予仅 `admin`/`system_admin` 可执行，拒绝与成功授予均落审计。
- 合同到期与付款逾期通知只发给数据范围内可见该对象的用户；逾期通知按派生口径触发，不依赖人工翻态；通知无处理闭环，只有已读/未读。
- 产权证风险不进入全局搜索，不单独建立风险处置流程，不提供关闭、忽略或已处理状态。

| 扫描件批量解析 | 如后续补录量证明必要，再设计批量上传、批量解析进度和批量任务治理；不得绕开单条人工确认规则 |
| 风险标签规则自动标注 | 从人工标注升级为规则自动加人工补充 |
| 主体合并 | 合并重复 Party，须先定义合并是否回溯改写历史客户主体数/合同数口径；MVP 只做建档查重、不合并（见 ADR-0020） |

## 11. 变更规则

- 产品目标态变更直接修改本文档。
- 字段、状态、统计口径变更同步修改 `docs/specs/domain-model.md`。
- API 或权限契约变更同步修改 `docs/specs/api-contract.md`。
- 实现追踪信息变更同步修改 `docs/traceability/requirements-trace.md`。
- 所有需求文档变更必须更新 `CHANGELOG.md`。
