# ADR-0028：资产运营 v5 以单一业务岗和事后登记为产品边界

**状态**：accepted（2026-10-22；取代 ADR-0023 至 ADR-0026，并收窄 ADR-0027）

资产运营 v5 只服务“资产管理岗”这一业务角色：系统接收已经在 OA、合同系统、银行或线下流程中完成的事实，维护资产单元、已签上游合同、已签终端合同、租金登记、委托管理费对账、出租率报送和档案，不建设招商意向、合同生效审批、银行流水认领、发票、催收案件、产权方门户或领导驾驶舱。平台管理员、组织、主体和数据范围仍是系统基础设施，不属于第二个业务岗位，也不得出现在资产管理工作台导航中。

所有业务视图都从“上游合同 → 资产单元 → 终端合同”及其追加事实推导。项目仅是管理归属标签，不是宗数、面积、出租状态或账款的事实源；台账、本月任务、报送说明、档案缺漏和完成率都是派生投影。上游尚未录入或终端租期超出上游时允许登记已经存在的终端合同并明确暴露风险，不把本系统改造成合同生效门。

## 后果

- ADR-0023 的“签署文书 × 项目经营记录”分层退出 v5；合同版本链直接维护在上游合同和终端合同上，项目不承载独立账款事实。
- ADR-0024 的授权冻结与生效阻断、ADR-0025 的外部审批证据门、ADR-0026 的催收账户/案件均退出 MVP。
- ADR-0027 仅保留“产权方实收终端租金 × 协议比例 → 双方盖章对账确认”的业务口径；发票轨、服务费收款分配和通用结算项不进入 v5。
- 收付款在外部完成，本系统只追加登记金额、日期、凭证和撤销原因；不得把登记记录反向解释为银行账或财务总账。
- 旧 v4.0 方案和规格只作历史迁移输入，不再作为产品验收依据。
