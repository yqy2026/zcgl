# ADR-0016: 企业微信推送按人定向（应用消息）——删群机器人广播，§8 自洽

**状态**: 🟡 已决策，待实施（2026-06-18）
**决策日期**: 2026-06-18
**相关需求**: REQ-NTF-001（通知域）、PRD §7.10、§8 非功能（权限/PII 外发）；相关 ADR-0006（删催缴工单）

---

## 背景

PRD §7.10 把企业微信推送写为「可选通道」，设计意图是把通知**按人推送到该接收人本人的企业微信**（个人消息触达）。但代码核对（2026-06-18，`services/notification/wecom_service.py`）发现实现用错了机制：

- `WecomService` 只往**一个共享群机器人 webhook**（`WECOM_WEBHOOK_URL`）发消息，群机器人**物理上无法按收件人隔离**（`mentioned_list` 只能 @人，不限制谁能看到内容）。
- `scheduler.py` 的 `_create_and_send_notification` 对**每个站内接收人**都调一次 `_send_wecom_notification`，每次把**完整正文**（合同号、租户名、应收金额）推到那个共享群。

后果：

1. **§8 违规外泄**：站内已按主体绑定数据范围过滤接收人（F1，ADR 簇 2026-06-15 已落地），但企业微信这头把业务正文广播到一个不可隔离的群——只要在群里，不管绑没绑该主体都能看到合同号/租户名/金额。PRD 自承「通知正文含业务数据，属业务数据外发渠道，受 §8 约束」，群机器人架构与该约束物理冲突。
2. **N 倍刷屏**：一条对象若 N 个用户在范围内，循环向群推 N 遍同一条。

## 决策

**企业微信推送改为按人定向的「企业微信应用消息」，删除群机器人广播：**

1. **机制**：按通知的 `recipient_id` 推**企业微信应用消息**（`touser` + `agentid`）给本人；新建配置 `corpid`/`agentid`/`secret` 与「系统用户 ↔ 企业微信 userid」映射。
2. **删群机器人**：下线 `WECOM_WEBHOOK_URL` 群广播路径——不可隔离的通道不允许承载业务正文。
3. **§8 自洽**：推给本人 = 自动落在其数据范围内（每条通知本就带已过滤的 `recipient_id`），不再外泄、不再 N 倍刷屏。正文仍可含合同号/租户名/金额，因为收件人就是有权看的人。
4. **语义=个人消息，不是企业微信「待办」**：推送是一条提醒消息（点开跳回系统看详情），**只有收到/已读，无完成态、无处理闭环**——与 CONTEXT「消息通知（提醒非工单）」一致；**不接入企业微信待办（todo）应用**，否则给通知接上处理闭环，重蹈催缴工单（ADR-0006）覆辙。
5. **可选通道纪律**：整条推送由配置开关控制；关 → 只走站内；开 → 必须按人推应用消息，**不允许回退群广播这种不可隔离通道**。在应用消息集成接通前，推送开关保持关闭、MVP 先只发站内（先止血，删掉泄露代码不等集成）。
6. 推送失败不影响站内通知创建，不做送达重试保障（沿用原约束）。

## 被否决的方案

| 方案 | 否决原因 |
|------|----------|
| 保留群机器人 + 正文脱敏（只推「您有 N 条提醒，登录查看」） | 群广播价值低、且「谁有提醒」仍泄露给全群；按人推本就能带正文，无须脱敏 |
| 保留群机器人 + 约束「群成员 ⊆ 可看全量数据者」 | 靠部署纪律兜 §8，易破、不稳，把安全边界外包给运维 |
| 企业微信「待办」（真 todo） | 给通知接处理闭环/完成态，违反「提醒非工单」，撞 ADR-0006 |
| 直接砍掉企业微信推送 | 通道已建、且按人推应用消息能合规承载，无须整体砍；仅砍群机器人这一错误实现 |

## 关键冻结决策

1. **企业微信推送按人定向（应用消息），不走群广播**。
2. **推送 = 个人消息，非企业微信待办**（无完成态、无处理闭环）。
3. **§8 由「推给本人」自然满足**，不靠群成员纪律兜底。

## 影响

待实施的工程项：

- **后端（先止血）**：下线 `WECOM_WEBHOOK_URL` 群广播；推送开关默认关、未接应用消息前只发站内。
- **后端（目标机制）**：新建企业微信应用配置（`corpid`/`agentid`/`secret`）与系统用户↔企业微信 userid 映射；`wecom_service` 改 `touser` 应用消息发送；`scheduler.py` 去掉「每接收人推一遍群消息」、改按 `recipient_id` 推本人。
- **PRD**：REQ-NTF-001 企业微信措辞改「按人推应用消息、非群广播、非待办」（本次随手落）。

- **traceability**：REQ-NTF-001 记代码收口缺口。
