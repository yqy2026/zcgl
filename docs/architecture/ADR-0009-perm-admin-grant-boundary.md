# ADR-0009: 权限管理员授予边界——业务角色不得由 `perm_admin` 授予

**状态**: ✅ 已实施（2026-06-15，2026-06-18 同步状态）
**决策日期**: 2026-06-15
**相关需求**: REQ-AUTH-001（会话安全与统一鉴权）、REQ-SYS-001（用户与角色管理）、PRD §5 角色权限模型

---

## 背景

PRD §5 与 2026-04-06 架构访谈 Q6 明文承诺：权限管理员（`perm_admin`）「**完全隔离**——只能管理用户、角色、权限配置，不能看业务数据」。

代码核对（2026-06-15）发现这是张空头支票：

- **授予端点对 `perm_admin` 开放**：`api/v1/auth/roles.py` `assign_role_to_user` 门控为 `require_any_role(["admin", "system_admin", "perm_admin"])`，`perm_admin` 在列。
- **service 层无授予范围校验**：`services/permission/rbac_service.py` `assign_role_to_user` 全程不检查目标角色是否超出授予人自身权限、不禁止给自己授权；授予后立即失效权限缓存。

后果是**结构性自我提权**：`perm_admin` 可 `POST /users/{自己}/roles` 授予自己 `asset_manager` 等业务角色，缓存刷新后当场看到全部业务数据。「完全隔离」实际只是「默认不分配业务角色」，而 `perm_admin` 手里握着撤销该默认的工具——边界可被持钥人单方捅穿。

**与已豁免的「职责互斥」性质不同，必须区分**：

- ADR-0002 / Q3 豁免的是**双人共谋**（审核人 ≠ 提交人、Deny/SoD 矩阵推迟到 vNext）——「不防两人串通」，可接受。
- 本问题是**单人独自越过 §5 明文安全边界**——承诺了却没兑现，是漏洞不是缓建功能。

## 决策

**补一条静态角色授予边界**（非互斥矩阵，不碰「MVP 不做职责互斥」红线）：

1. **角色按业务数据能力二分**：带业务数据访问范围的角色为「业务角色」（如 `asset_manager`、`project_manager`、运营/业务审核类）；只涉及用户、角色、权限配置、字典、审计的角色为「管理角色」（如 `perm_admin`）。
2. **`perm_admin` 不得授予业务角色**：含授予自己；`perm_admin` 只能授予管理角色，保留其本职（用户 CRUD、角色定义、权限配置、字典、审计）。
3. **业务角色仅 `admin`/`system_admin` 可授予**。
4. **授予前分类校验，违规拒绝并审计**：拒绝与成功授予均落权限审计日志。
5. **校验落在 service 层**（`rbac_service.assign_role_to_user`），不只在端点门控，避免绕过 API 层的调用路径。

## 被否决的方案

| 方案 | 否决原因 |
|------|----------|
| 维持现状（`perm_admin` 可授任意角色） | §5「完全隔离」设计层即假，单人可自我提权看全量业务数据 |
| 把 §5 措辞降级为「默认不分配业务角色」、风险推 vNext | 等于承认安全边界不存在；与已建成的 ABAC/数据范围体系的安全基调矛盾，且 2026-04-05 review 已将 perm_admin 设计标 P0 |
| 引入完整可配置职责互斥矩阵 | 超出 MVP，与「MVP 不做职责互斥」冲突；本问题用静态角色授予边界即可闭合，无需流程引擎 |
| 仅在端点门控加校验 | 业务逻辑须在 service 层（项目架构原则），且端点层校验易被其他调用路径绕过 |

## 关键冻结决策

1. **隔离是强约束非默认**：`perm_admin` 对业务角色的授予能力被静态禁止，含授予自己。
2. **静态角色授予边界 ≠ 职责互斥**：本决策不引入审核人/提交人互斥或冲突矩阵，与 ADR-0002 共存。
3. **业务角色授予收敛到 `admin`/`system_admin`**：`admin`/`system_admin`/审计类用户可按授权查看全量数据，符合 §5「管理员和审计类用户可按授权查看全量数据」。

## 影响

已实施的工程项：

- **后端**：`rbac_service.assign_role_to_user` 已增加授予边界校验：授予人仅具 `perm_admin` 时不得授予业务数据角色（含授予自己），业务角色仅实际持有 `admin`/`system_admin` 的授予人可授；拒绝路径写入 `role_assign_denied` 审计，管理角色授予保持可用。
- **PRD**：§5 核心规则、REQ-AUTH-001、§9 验收项已改（本次决策随手落）。
- **CONTEXT.md**：增「权限管理员授予边界」词条（本次决策随手落）。
- **traceability**：REQ-AUTH-001 已记录代码收口证据。
