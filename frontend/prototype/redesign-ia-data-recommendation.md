## 3. 逐类替换映射建议（核心）

### 3.1 运营项目（`SCOPE_DATA` / `ROLE_CONFIG.scope`）
- **删除** `东城园区一期/二期`、`滨湖科创园` 三个虚构园区。
- **替换为**真实项目维度（二选一，建议 A）：
  - **A（推荐，贴合台账 9 分表口径）**：`工经`（广州市工业经济发展有限公司）、`饮食`、`红棉`、`工贸`、`集团`、`鼎晟`、`安居`、`广源`，并可保留一个 `合计` 汇总项。原型 `p1/p2/p3` 三档扩展为上述多档即可。
  - **B（贴合资产项目视角）**：`白云山翠竹园`、`沙面黄沙码头`、`长堤大马路358–364号`、`北京路249号前座`、`江南苑`、`人民北路宁家里29号`、`赤塘大街29号`、`东川路90号`。
- `SCOPE_DATA` 中各项目的 `rentable/blocked/soon/arrears/vac[]/arr[]` 须改为对应真实口径（见 §3.7–3.8 口径守卫），**不得保留虚构的 979/608/600 ㎡ 与 ¥864,200 等**。

### 3.2 空间/物业（`SPACES[]` / `DETAIL{}`）
- **删除**全部 `A301/B101/P118/B2-01` 等虚构房间。
- **替换为**真实房屋资产（取自 §1.2）：至少富化以下样本，其余按判定生成：
  - `人民北路宁家里29号_802`（40.13㎡，住宅，有证，房地产权属证号280898，消防宿舍）
  - `人民北路宁家里29号_801`（39㎡）
  - `赤塘大街29号_108`（27.08㎡，宅基地证031417，海珠区）
  - `东川路东仁新街1号101房`
  - `赤塘大街29号_自编305房`
- `SPACES` 字段映射：
  - `id` → 资产名称（如 `宁家里29号_802`）；`bld`（楼栋）→ 真实楼栋名（人民北路宁家里29号 / 赤塘大街29号）；`fl`（楼层）→ 真实楼层（801/802/108…）；`proj` → §3.1 项目维度；`area` → 真实建筑面积；`price` → **删除"元/㎡·天"虚拟单价**，改挂真实月租（§3.7）；`lease` → 真实乙方（取 §1.3 同资源合同）；`st`（状态）→ 按真实占用/权证/整改派生（详见原型既有"可租状态由有效合同/维修封闭/有效限制推导"规则，无需虚构）；`next`/`ctx` → 真实账单日/在谈信息。
- `DETAIL` 富化对象改为上述真实资产；`rights` 中的"产权/权证号/权属人"直接用 §1.2 真实值，`底价` 字段改为真实政府指导价（§3.7），`当前合同` 关联 §1.3 真实合同号。

### 3.7 价格/租金口径（重要口径守卫）
- 原型的 `price`（2.70–3.10 **元/㎡·天**）与真实系统**口径不一致**。旧系统合同以 **"初始租金(元)"（月租）** 与 **"政府指导价"** 计，**不按元/㎡·天**；且车位（江南苑）按个计、住宅按套计，面积可能为 0。
- **建议**：`SPACES.price` 改为真实月租（元），单位标注"元/月"；底价字段对应"政府指导价"；住宅/车位注明"按套/按个计租，面积可不填"。已知真实参考值（来自既有工作记忆，落地前再核对）：江南苑停车场月租 **485–510 元**；东川路90号采用**按天分摊**逻辑（月租 ÷ 30 × 实际天数）。**这些口径差异必须在原型注释与走查说明中明确，避免误导。**

### 3.8 金额/账款（`SCOPE_DATA.arrears` / `ROLE_CONFIG.metrics/tasks`）

- `ROLE_CONFIG` 的 **8 个岗位视角（招商运营/出纳/财务复核/催收运营/现场物业/资产权属/项目负责人/管理层/产权方协同）属于角色原型（archetype），建议保留**——它们是信息架构走查对象，不是具体人物；只需把 `team/scope` 文案按 §3.1/§3.5 落真实即可。

## 4. 不建议替换、建议保留为"原型示意"的部分

以下属于**交互/流程原型**而非业务实体，保留虚拟不影响"用真实业务信息替代"的目标：
1. **岗位视角与走查路线**（`ROLE_CONFIG` 的 8 个角色、`走查路线`）：作为 IA 走查对象保留。
2. **状态机与阻断逻辑**：可租/在租/受限/权利待核实、生效阻断、越权拦截、追加不覆盖等——这些是规则原型，绑定真实字段名（如"房地产权属证号280898""五羊司合字[2025]312号"）即可，无需虚构新实体。
3. **演示性金额若暂时无真实值**：允许保留占位但必须加"原型示意/脱敏"角标，并在页脚注明"数据为演示，正式数值以旧系统 X 报表为准"。
4. **按钮/表单交互文案**（如"＋登记租赁意向"）：保留，仅把其中的示例名（山丘咖啡等）替换为 §3.4 真实客户。

## 5. 落地注意事项与口径守卫

1. **租期口径**：旧系统合同以"签订/开始/结束日期 + 租赁期限（月）"表达（如 2026-06-01 → 2029-05-31，36 月），原型 `lease` 字段的"至 2027-05"等须改为真实结束日期格式，不要混用虚构年份。
2. **面积口径**：住宅/车位按套/按个计，面积可能为 0（如 `A07` 合同面积 `0.0000(㎡)`），原型 `area` 不得强行套用虚构的 13–800㎡。
3. **金额单位**：统一"元/月"或"元"，禁用"元/㎡·天"虚构单价；东川路90号保留"按天分摊"特殊逻辑。
4. **命名规范**：合同/意向/委托/对账单/催收案一律采用旧系统真实前缀（`五羊司合字[YYYY]NNN号` 等），删除 `HT-/IN-/WT-/STMT-/CA-`。
5. **数据脱敏**：真实客户姓名（池玉銮、吕巨建、尤在永为自然人）在对外走查原型中建议做脱敏或加"真实样本"标注，避免直接暴露个人承租信息；企业客户（回民饭店等）可如实呈现。
6. **来源可溯**：每条替换值建议在原型注释或走查文档标注来源模块（资产台账 / 合同台账 / 欠费报表），便于后续与台账 Excel（承租合同台账2026.xlsx 等）交叉校验。
7. **规模守恒**：`SCOPE_DATA` 的项目汇总必须与 §3.1 选定维度一致；若选 9 分表口径，`all` 应为各分表之和。
