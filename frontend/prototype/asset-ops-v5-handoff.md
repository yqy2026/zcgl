# Handoff：资管运营 · 资产管理岗工作台（v5）

> 本包对应项目中的 `资管运营原型 v5.dc.html`（2026-10-22 同步）。包内 `资管运营原型.dc.html` 与它逐字一致。

## 概述

本包替代 `frontend/prototype/redesign-ia.html`（v4.0，22 页、3 套导航）。重构依据是资产管理岗的真实职责：

1. 承接和产权方签好的**承租合同 / 委托管理协议**（签订在 OA 和合同系统完成，本系统只管签订之后），知道哪些要到期，支付承租租金，对账计算委托管理费；
2. 维护**物业台账、承租租金台账、终端租金台账、委托管理费台账**；
3. 维护存量经营性物业台账，**每月 1 日报送上月**出租率；
4. 归档**产权证、承租合同、终端合同**扫描件。

侧栏入口：**本月 / 报送 / 物业 / 合同（上游合同、终端合同）/ 台账 / 档案 / 数据导入**。旧原型里的意向、审批、生效检查、银行到账核对、催收、产权方门户都不在本岗位范围内，不要实现进这套导航。

## 关于设计文件

原型是**用 HTML 做的设计参考**，不是生产代码。请在现有前端工程（`frontend/`，React + AntD + `variables.css` / `themeConfig.ts`）里按既有模式重新实现。原型样式全部内联，实现时改用 CSS 变量和 AntD 组件。

原型的逻辑代码里有一个 `db()` 方法：**上游合同 → 资产单元 → 终端合同**三张表是唯一数据源，所有页面（本月、台账、报送、档案）都从它推导。这正是建议的后端数据结构，可以直接参考其中的推导规则（出租状态、应付计划、到期天数、档案应有份数等）。示例数据本身不是需求。

## 保真度

**高保真。** 布局、信息层级、文案、状态色、交互都是终稿。颜色和尺寸映射到 DESIGN.md 的 token（见文末），不要照抄十六进制值。原型和 DESIGN.md 冲突处见 `DESIGN-patch.md`。

## 核心领域规则（实现前必读）

| 规则 | 说明 |
|---|---|
| 两种模式 | **承租模式**：产权方 →（承租合同）→ 本公司 →（终端合同 · 转租）→ 终端租户。本公司向上付租金、向下收租金。**委托管理模式**：产权方 →（委托管理协议）→ 本公司受托；产权方 →（终端合同 · 直签）→ 终端租户。本公司不经手租金，按实收收管理费。 |
| 三类合同 | 承租合同、委托管理协议（统称“上游合同”），终端合同（“转租”“直签”两种）。全系统统一用“委托管理费”“委托管理协议”，不用“代理费”“代理协议”。 |
| 挂接 | 每份终端合同挂在一份上游合同下，落到一个或多个资产单元上（**合并出租**：一份终端合同覆盖多个单元，各单元仍分别计宗）。出租方由上游模式自动决定：承租→本公司，委托→产权方。 |
| 上游尚未录入 | 录入终端合同时允许选“上游尚未录入”。**宗按物业（资产单元）计算**：单元有在租终端合同即算已出租，与是否挂上游无关，照常计入出租率和押金台账。终端合同列表“上游合同”列显示黄字“未录入”，补录上游后改挂。 |
| 租期越界 | 转租合同租期止日晚于承租合同止日时标红提示（不阻断保存）。 |
| 上游已到期未处理 | 上游合同到期后既未续签也未退出在管：本月页红色常驻提醒；期间单元仍按在管计宗，名下终端合同显示“暂无上游依据”。 |
| 资产单元 | 物业台账最细一层，= 最小可租单元，计 1 宗。**项目只是管理归属标签，任何汇总都不能从项目推导**，只能从资产单元逐行加总。 |
| 拆分 / 合并单元 | 原单元从生效日前一天停止计宗，新单元从生效日起计；历史月份不变。合并只能在同一份上游合同内。 |
| 出租状态 | 由“当月最后一天有无在租的终端合同”派生，**不可手改**。空置单元可填“空置原因 + 预计起租”，只作备注，不影响计宗。 |
| 纳入报送（年度考核范围） | 按年度、按资产单元逐宗勾选，默认全部存量经营性物业纳入；不纳入必须填原因。抽屉内修改先是草稿，“保存考核范围”后生成新版本（v1、v2…），从当月报送起生效；底栏实时显示出租率变化预览，注明已报送月份不变。年中新增单元**确认前不计入报送**，在本月页提醒确认。数据模型：`考核范围(年度, 版本, 资产单元, 是否纳入, 原因, 操作人, 时间)`。 |
| 土地面积 | 绝大多数单元为 0，只有宗地和园区类单元有值，不做分摊。 |
| 承租租金支付 | 付款在系统外完成，本系统**登记一笔**：实付金额（默认应付额，可改）、日期（默认今天）、凭证可选。少于应付额记为“部分付款 · 欠 ¥x”。付款计划由合同条款生成：**递增自动叠加**（如“每 3 年 +5%”）；**季付**只在季初月份出应付（季初从起租月起每 3 个月算；付款日按合同约定，录入默认月付 25 日前、季付 15 日前）。 |
| 终端收租 | 转租单元由本公司收取，本月页和“终端租金（应收）”台账登记到账（同样支持部分到账）；未到账的往月一直挂着，不随月份消失。委托单元由产权方收取，本系统只登记“产权方已报到账”。 |
| 委托管理费 | 基数 = **产权方实际收到的**终端租金 × 协议比例。上月到账登记齐后出对账单；**当月 31 日仍未收的户顺延到下月**，不卡住当月对账。每个产权方每月一张对账单，双方盖章并上传后才算确认。已盖章月份的基数锁定，事后改合同不影响。 |
| 押金 | 分四类：**应收未收 / 应付未付 / 应退未退 / 应收回**（2026-10-27 SSOT 增补“应付未付”：承租合同押金我方尚未付清；本原型未演示该类）。**委托管理协议没有保证金**（原型委托合同详情里的“履约保证金”不实现）。金额写成“欠 ¥40,000 / 共 ¥80,000”。终端合同：约定月数 × 月租；收取方（转租→本公司收，合同结束后可抵扣欠租，终止时默认自动抵扣；直签→产权方收，本系统只登记，不提供“抵扣”）。续签时押金整体转入新合同，不退回。口径以 `docs/specs/domain-model.md` §4.18 为准。 |
| 终止 / 退租 | 终端合同在抽屉里“终止 / 退租”：选类型（到期 / 提前 / 协商）、退租日期、房屋交接、押金结算。终止后合同进入历史，只读。 |
| 到期不续签 · 退出在管 | 只在上游合同详情里操作（本月页只放“查看合同”）。名下仍有在租终端合同时不允许退出，列出并提供“去终止”。 |
| 报送门槛 | 报送前核对分“必须”和“建议”两档。“必须”项（会改变分母）未清零、或较上月有变动但变动说明未填时，“标记为已报送”置灰并写明原因。 |
| 报送快照 | “标记为已报送”后锁定当月快照（连同当时的考核范围版本），之后台账再改也不影响已报出的数；台账与快照不一致时出黄色提示。撤回报送须填原因，原快照保留在变更记录里。 |
| 撤销类操作 | 撤回报送、撤销付款 / 到账登记、撤销终止、撤销退出在管、撤销导入批次：一律弹窗填原因，写入变更记录。 |
| 变更记录 | 谁、何时、改了什么、（撤销类）原因。报送页展示当月记录，可一键引用到变动说明。 |
| 档案 | 不单独存文件：每份扫描件挂在某个资产单元或某份合同上，档案页只是按类型集中起来看。 |
| 产权证 ↔ 资产单元 | **多对多**：一本证可覆盖多个单元，也可一个单元一本证。档案“应有产权证”按证计数，另统计“未关联任何产权证的单元”；物业详情显示“本证覆盖 N 个单元”。 |
| 到期提醒 | 统一提前 **180 天**：剩余 ≤90 天红色，90–180 天黄色。 |
| 版本链 | 续签合同录入时选择“续签自”哪一份，形成链条：旧合同 → 当前 → 续签（OA 审批中 / 已签待生效）。旧版本只读，点开显示灰色横幅“回到当前版本”。续签不改单元。 |
| 数据导入 | 两种模式。**新增数据**：一个 Excel 三张表（资产单元、上游合同、终端合同），编号已存在时报错；新接管单元从接管日起计宗。**更新已有数据**：先导出现有台账，改完上传；按单元编号 / 合同号匹配，只改填了的列，留空不动；派生字段（出租状态、计宗等）不能导入，填了也忽略；未匹配的行报错（更新模式不新增）。上传后逐条列出“现值 → 新值 → 影响”，可逐条取消勾选，确认后才覆盖。两种模式都是错误清零才能写入、提醒不拦截；每次是一个批次，7 天内可整批撤销（更新批次撤销须填原因）；已报送月份不变。 |
| 角色 | 只有资产管理岗一个角色：不做领导只读视角，不做按人分配待办。 |

## 全局布局

- 外壳：左侧导航 188px（白底，右侧 1px 边框）+ 内容区（`--bg-layout`）。最小宽度 1280px，1280px 下不能横向溢出（台账 12 个月表格除外，表内横向滚动）。
- 导航：本月（右侧显示未完成件数）/ 报送 / 物业 / 合同（分组标题，不可点）/ 上游合同 / 终端合同 / 台账 / 档案（右侧红字“缺 N 份”）/ 数据导入。底部是用户头像、姓名和岗位。
- 选中项：`--primary-light` 底 + 主色文字 + 600；未选中为次级文字色。
- 页面骨架统一为“**列表 + 右侧详情栏**”：宽 280–330px，常驻右侧，不弹层、不跳页。单击行选中，详情栏随之切换。
- 每页只有一个实底主按钮，其余为描边样式。
- 报送页、对账单页从本月卡片进入时顶部显示“← 返回本月”；从侧栏进入时不显示。

## 页面

### 1. 本月（首页）

- 页头：小字日期行，大标题“本月还有 N 件没做完”（24px/600）；右侧完成进度条（260×6px）。**只计有截止日的事**（下方 4 张卡），“随时处理”区不计入。
- 四张任务卡，2×2：
  1. **支付 N 月承租租金**（月付 25 日前 · 季付 15 日前）：每笔一行，按逾期 → 今天到期 → 未到期排序。点行打开登记卡（见规则“承租租金支付”）；已完成的折叠为“已完成 n 笔”。往月未付的一并列出并标逾期天数。
  2. **收取 N 月终端租金**（转租单元 · 本公司收取）：列出全部未到账的户，已到账折叠；底部“终端租金台账 →”。
  3. **N−1 月委托管理费对账**：每个委托物业一行，公式 + 状态：`收租中`（黄，显示“产权方已收 a/b 户 · 10-31 仍未收的顺延下月”）、`待盖章`（蓝）、`已确认`（绿）。底部流程提示：登记产权方到账 → 出对账单 → 双方盖章对账单 → 确认。
  4. **报送 N 月存量经营性物业台账**：按宗出租率（30px/600）、“m / n · 较上月 ±x”（口径变化时注明）；较上月变动的单元；“打开报送页”，旁边红字显示报送门槛未满足的原因。
- **随时处理**（不计入进度）：上游已到期未处理（红框，通栏，有才显示）/ 半年内到期的上游合同（可点进合同）/ 档案缺漏（按类型汇总，可点）/ 押金待处理（通栏，四类）/ 年中新增单元是否纳入考核（黄条，“查看 / 今年不纳入 / 确认纳入”）。处理完毕后条目自动消失。
- 每月 1 日自动生成新一期，上月未完成事项带入并标注拖延天数。

### 2. 报送（出租率报送）

- 顶栏：标题、状态标签、门槛提示（红字）、**“考核范围 当前 vN”按钮**、“导出 Excel”、“标记为已报送”（主按钮；已报送后变为描边“撤回报送…”）。草稿始终实时计算，**没有“刷新数据”按钮**，时间戳只在快照上显示。
- **报送记录**：按月横排小卡片（月份、出租率、“MM-01 已报”），最后一张是当月草稿。点已报月份进入**快照只读态**：灰色横幅（报送人、日期、考核范围版本，“下载当时的报送表”“回到草稿”），4 个要点（宗数、已出租、出租率、较上月）；快照与现台账不一致时出黄色差异提示。
- 草稿态内容（自上而下）：
  - 本月剔除考核（红框，有才显示）：列出不纳入的单元和原因。
  - **较上月变动说明**（左）：系统列出变动，下方文本框；有变动时必填。**报送前核对**（右）：每条带“必须 / 建议”标签和处理按钮，就地处理不跳页。
  - **变更记录**：时间 / 操作人 / 内容 / 原因；“引用到变动说明”。
  - **报送说明**：句式固定（逐字照搬），数字自动填入并浅蓝底高亮：
    > 2026 年 10 月份，
    > 1、公司在管存量物业项目 {5} 个（其中经营性项目 {4} 个，非经营性公房项目 {1} 个）。
    > 2、存量土地面积约 {x} 万平方米，存量物业建筑面积约 {x} 万平方米。
    > 3、存量经营性可出租土地物业面积约 {x} 万平方米，经营性已出租土地物业面积约 {x} 万平方米。
    > 4、在管经营性存量物业共 {n} 宗，已出租 {m} 宗，按宗数计算出租率为 {m/n}。
    - 经营性项目数 = 明细表中不同项目的个数；万平方米、出租率保留 2 位小数；第 2 条含非经营性公房。时点 = 当月最后一天。
  - **明细表**：每宗一行，不做项目小计。列（顺序固定）：产权方 / 业态类别 / 项目名称 / 物业地址 / 土地面积(㎡) / 经营性可出租面积(㎡) / 经营性已出租面积(㎡) / 可出租物业数 / 已出租物业数 / 出租率（按个数）。表头和合计行固定；未出租行浅黄底；可切换“全部 / 只看未出租”。
- **考核范围抽屉**（右侧滑出 520px，带遮罩——这是唯一的浮层抽屉）：标题旁显示当前版本；筛选全部 / 已纳入 / 未纳入；“从上一年度复制”（**实现时先提示会覆盖几项**）；按地址分组，组头三态复选框 + “纳入数 / 总数”，展开到逐宗；未纳入的单元下方填原因，未填红字提示；底栏：纳入 / 不纳入宗数、未填原因数、“有未保存的修改”、出租率变化预览；“放弃修改”“保存考核范围”（有未填原因时置灰）。

### 3. 物业（物业台账）

- 顶栏：分段筛选（全部 / 纳入报送 / 空置可租 / 不可租·非经营 / 缺产权证，带数量）、项目下拉、搜索框（地址、单元、租户、产权证号）、“导出台账”、“批量导入单元”（→ 数据导入）。**新增单元只走数据导入**，不再有单个新增按钮。
- 表格**按项目分组**，组头可折叠、吸顶。列：资产单元（名称 + 小字项目）/ 业态 / 产权方（简称）/ 建筑面积㎡ / 可租面积㎡ / 性质 / 2026 考核（纳入 / 不纳入 / 待确认）/ 出租状态（已出租蓝、空置可租绿、不可租灰；第二行“租户 · 至 日期”）/ 产权证（有 / 缺红字）。
- 详情栏：出租状态 + 考核标签；基础信息；**租赁时间轴**（上层终端合同、下层上游合同、斜纹为空置、红线为今天，可点段落）及合同列表；空置时显示“空置原因”（装修中 / 招商中 / 待收回 / 有意向未签 等）+ 预计起租；产权证卡片（缺失为红色虚线框 +“上传”）；合同链；底部规则说明；“编辑基本信息”“拆分 / 合并单元”。
- **调整资产单元弹窗**（580px）：拆分 / 合并两个页签，生效日期；拆分逐行填编号和面积并校验面积合计；合并选同一上游内的单元并填新编号；底部蓝色块说明对计宗的影响。

### 4. 合同 › 上游合同

- 左栏 240px：搜索框（同时命中终端合同）、主按钮“＋ 录入已签合同”（预选承租合同）、按“承租合同 / 委托管理协议”分组的列表（名称、到期信息按颜色、“产权方 · 终端 N 份”）。
- 中栏：
  - 头部：类型标签、合同号、合同名、双方；右上到期框（≤90 天红底、≤180 天黄底，否则显示日期）。查看旧版本时出灰色横幅。
  - 条款格子：月租金或管理费比例、租期、付款或结算方式、递增、押金（仅承租合同；委托管理协议无保证金）。
  - **版本链**：旧版本灰底、当前版本黑底白字、续签中的版本黄色虚线，用 → 连接；末尾“＋ 登记续签合同”（打开录入弹窗并预填“续签自”和原合同各方）和“到期不续签”（打开退出在管弹窗）。
  - 扫描件标签：缺失的红色虚线并标“缺”。
  - **付款计划**（仅承租合同）：按递增阶段分行——期间（含“首期租金 / 第 N 次递增 +x%”）、月租金、期数、进度（进度条 +“已付 a/b · 下期 YYYY-MM”）、合计。当前阶段浅蓝底。金额 = 首期 × (1+递增率)^阶段数，取整到元。
  - **资产单元与终端合同**：单元 / 面积 / 终端租户（空置显示绿色“空置 · 可租”）/ 终端合同号 / 租期至（越界红字）/ 月租金 / 扫描件。表头右侧注明终端合同出租方。
- 详情栏：所选终端合同详情（越界红色提示、字段、扫描件与版本）；“下载 / 外发”“登记补充协议”。**默认不自动选中**会更清楚——v5 原型仍默认选中第一份越界合同，实现时以“未选中时显示提示文字”为准。

### 5. 合同 › 终端合同

- 筛选：生效中 / 180 天内到期 / 租金未到账 / 押金未结清 / 缺扫描件 / 已结束，每项带数量。搜索含已结束合同。
- 表格列：终端租户（含合同号）/ 资产单元（合并出租显示“合并 N”）/ 模式（转租、直签）/ 上游合同 / 租期至（越界红；≤90 天黄）/ 月租金（第二行本月到账状态）/ 押金或保证金（金额 + 收取方 · 状态）/ 扫描件。
- 详情栏：历史合同时灰色横幅 + 前后版本链接；字段；本月收租块（转租：登记到账；直签：登记产权方已报）；押金明细；到期前“续签这份合同”；“登记到账 / 退还”类押金按钮、“终止 / 退租”。
- **终止 / 退租弹窗**（580px）：类型三选一、退租日期、房屋交接、押金结算明细、蓝色影响说明。押金结算默认按欠租从早到晚自动抵扣，可取消或调整；提前退租的“免租优惠补收”金额与依据由用户填写，不自动计算（SSOT 2026-10-27）。

### 6. 录入已签合同（弹窗，760px）

1. 上传盖章扫描件（左侧 200px 拖放区，**必须真的上传**，未上传不能保存）；
2. 类型：承租合同 / 委托管理协议 / 终端合同（三卡单选，按入口预选）；
3. 第 2 步随类型变化：上游合同选产权方、资产单元、OA 审批单号；终端合同选上游合同、资产单元（**可多选 = 合并出租**；与在租合同冲突时红字提示）、承租方；出租方自动带出只读；
4. 核对识别出的条款（可改），越界格子红框；
5. （承租 / 有租金表时）核对租金计划：期间、原定月租金（可改）、免租减免、实际月租金、较上年、核对结果；免租期块：月数、减免方式、优惠合计、提前退租追回说明。
- 底部：保存条件不满足时按钮置灰，**左侧写明缺什么**；“取消”时有未保存内容会保留草稿；保存后扫描件自动进入档案，并提示。

### 7. 台账

- 页签：**承租租金（应付）/ 终端租金（应收）/ 委托管理费**。出租率不再在台账里出现（只在报送页）。
- 统一表格：行 = 合同或物业，列 = 2026 年 1–12 月（当前月主色，未来月灰），右侧合计，底部合计行。表格可横向滚动。
- 承租租金：已付金额 / 待付（蓝）/ 逾期（红）/ 部分。终端租金：同上。委托管理费：已确认（金额）/ `待盖章`（蓝）/ `收租中`（黄）/ `未到`（灰），合计只统计已确认。
- 格子可点，详情栏展示“这个格子是怎么来的”（依据条款、期限、凭证、记录人），并提供对应的登记 / 撤销按钮。

### 8. 委托管理费对账单（从本月进入，每个产权方每月一张）

- 纸面样式：最大宽 760px，1px 深色表格线。标题“委托管理费对账单” + 编号。
- 抬头：委托方（产权方）/ 受托方（**实现时填公司全称**）/ 依据协议 / 对账期间。
- 明细列：序号 / 物业地址 / 承租方 / 所属期 / 物业月租金金额（元）/ 实收月租金金额（元）/ 计费比率 / 收费金额（元）/ 备注（未收户注明顺延）。金额 2 位小数，千分位。
- 合计行，“收费金额合计（大写）……（小写 ¥…）”，双方盖章栏和日期，附件说明。
- 顶栏：状态标签、“打印”、“上传盖章件”（主按钮）。

### 9. 档案

- 顶部：4 个完成率（产权证 / 上游合同（含补充协议）/ 终端合同扫描件 / 交接书或对账单），“已有 / 应有 · %”+ 4px 进度条；右侧拖放区。**实现时支持一次拖入多份**，按文件名或识别结果自动配对，给出“待确认配对”列表。
- 矩阵：行 = 物业分组，列 = 产权证 / 上游合同正本 / 补充协议 / 终端合同 / 交接书·对账单。“已有 / 应有”：齐全绿底，缺失红底，不适用灰“—”。
- 应有份数由系统推导：每本产权证 1 份；每份在租终端合同 1 份；每份上游合同 1 份正本；委托模式每月 1 张对账单。
- 详情栏：所选格子的文件清单，已有和缺失都列出，缺失项红色虚线框 +“上传”。

### 10. 数据导入

- 顶部分段切换：**新增数据 / 更新已有数据**。
- 新增数据：四步条（下载模板 → 上传并校验 → 处理问题 → 确认导入）。1 · 模板说明；2 · 上传后按表显示行数 / 通过 / 错误 / 提醒；3 · 问题列表（错误 / 提醒页签，每条：级别、位置、问题、处理方法、就地处理按钮），“重新上传修正后的文件”；4 · 影响预览，“确认导入”。导入后可“撤销本批次”“去物业查看”。
- 更新已有数据：1 · 导出现有台账；2 · 上传并核对差异——差异表（勾选 / 资产单元 / 字段 / 现值（删除线）/ 新值（加粗）/ 影响），下方列错误和提醒（“单元编号不存在 · 跳过这一行”“出租状态列已忽略”）；3 · 确认更新——影响预览（更新几处、面积变化、宗数和出租率不变、已报送月份不变），“确认更新 N 处”，完成后变为“撤销本批次”。原型里更新会真实改写物业台账和报送面积。
- 右栏：导入批次列表，两种模式的批次混排。

## 交互与状态

- 所有列表：单击行即选中，左侧 2px 主色内阴影 + `--primary-light` 底，详情栏同步。切换筛选后原选中项不在结果中时，自动选中第一行。
- 所有“去处理 / 查看”跳转都带上目标对象并就地打开，不只跳到页面。
- 每个列表和详情栏都有**加载 / 空 / 无权限 / 出错**四种状态，见 `状态规范.dc.html`。无权限必须和空区分，不能返回空列表伪装成功（PRODUCT.md 原则 3）。
- 空状态的录入按钮在所有情况下都显示（只有一个角色）。
- 置灰的按钮旁边必须写明原因。
- 不用 emoji 图标；不写解释性页面副标题，规则只在相关操作旁出现。

## 状态与数据（前端视角）

- 派生字段只读：出租状态、纳入报送、到期剩余天数、档案应有份数、委托管理费金额、付款计划、各类合计。
- 手工维护：资产单元物理信息、空置原因、合同条款（识别预填后人工确认）、付款 / 到账登记、押金收退、盖章件上传、考核范围、报送变动说明。
- 当月任务清单由后端按月生成，未完成事项结转到下一期。
